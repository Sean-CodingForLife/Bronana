## 对局体检：把"好不好玩"变成量得出来的东西（**已完成**）

> 起因："你是否都实现了，并且你自己玩了以后认为很好玩，你需要找外部参考对比。"

### 一、先说清楚"自己玩"在这里等于什么

我没有手，所以"自己玩"= **写一个像玩家的 bot，跑 24 局，量八项代理指标**，
再拿这些数字去对公开设计基准。工具是 `pnpm run fun`（`tools/fun-audit.mjs`）。

它和探针（`tools/bug-probe.mjs`）**共用同一份自动玩家**（`tools/_run.mjs`）。
这一点是踩出来的：第一版各写一份，结果**同一个种子跑出两个完全不同的结果**
（探针到第 15 波、体检第 3 波就死）—— 那比没有工具更糟。现在两份实现收成一份。

### 二、体检逮到三个真 bug（都不是我预料到的）

| # | bug | 它造成的后果 | 修法 |
| --- | --- | --- | --- |
| 1 | `enterRoom(9)`（越界方向）把状态机从 `shop` 打回 `playing` | **整条商店经济失效**：`buyOffer` 从此全是"当前不在商店界面"。实测一局试买 4 次、成功 **0** 次 —— 玩家看到的是"我明明还在商店里，怎么买不了了" | 三道校验全部先过，**状态切换放到最后**（"失败的无副作用"对状态机也成立） |
| 2 | `walls` 的键不含层号，读档只重建当前层的地图 | 三层跑到第 2 层读档，**别的层的破墙记录被当成坏档丢掉**（2 条 → 1 条）：已打穿的暗门又"裂"回去了 | 键改成 `层号\|房A\|房B`；读档按层号隔离，不再回表校房间 |
| 3 | `offers` 容器的 `cap: 12` 是照着早期数值写的 | 货架件数随进度合法增长（据点货架 + 商店房 +2 + 契约），到 16 件时**容器不变量报假警** | `cap: Infinity` —— 真正的约束在 `market.ts` 的 `n` 那一行，不在这里重复一遍 |

第 1 条是关键：它**不是崩溃、不是报错、不是任何测试会红的东西** ——
它只是让玩家"买不了东西"。而这种故障最贵：游戏照常跑、画面照常动，
但整个 roguelite 的核心乐趣（在商店里做构筑决策）被静默关掉了。
抓到它靠的是"体检里有一个指标恒为 0"（构筑决策密度）——**一个量得出来的 0 比一句"感觉不对"值钱**。

## 三模块按规划重塑（**进行中**）—— 货币表与钱包

> 用户拍板的三条（我逐一问过）：
> ① 局内只留「制造」，营地与据点合并成局外的经营屏；
> ② 给经营一个**独占货币**（孢子归养成）；
> ③ **"材料是能带得出去的，也不该是在局内消费的"**。

### 一、这一步把货币的四个身份定下来了

改造前的货币表有一处**从头到尾都是错的**：注释写着"经营花材料与核心材料"，
而 `材料` 是 `session` 档（结算清零）—— 它**根本买不了局外设施**。
真相是 `Profile.keepBuy` 当时扣的是 `data.spores`。
这个错不是打错字，是**概念混了**：一笔钱同时被当成"局内的通用零钱"和"经营的主币"。

现在拆成两个身份，各自只干一件事：

| 货币 | 档 | 从哪来 | 花在哪 | 状态 |
| --- | --- | --- | --- | --- |
| **废料** | 局内（session） | 战斗：刷怪 + 清间 | **只在局内**：商店 / 制造 / 刷新 | 🚧 表已定，字段还没改名（见"还没做"） |
| **材料** | 跨局（bridge） | 战斗：刷怪 + 清间，**带出局** | **只在经营**：盖设施 / 建筑 / 产线 | ✅ 已接（钱包 + 据点） |
| 孢子 | 跨局（bridge） | 战斗：结算按深度 | **只在养成**：天赋树与洗点 | 🚧 表已改（去向从 `manage+grow` 收窄成 `grow`），洗点还没改 |
| 核心材料 | 关键（meta-rare） | **只有关底 Boss** | **经营与养成的共同门槛** | ✅ 本来就是这样 |
| 合金 | 跨局（bridge） | 回收装备 | 养成：图纸 | ✅ 本来就是这样 |

**钱包（`Profile.wallet.material`）** 是"带出去"的落点，只有三个出口：

```ts
Profile.material()          // 读
Profile.addMaterial(n)      // 结算入账（applyRun）
Profile.spendMaterial(n)    // 花；不够就**不扣**并返回 false
```

### 二、一个必须写清楚的取舍：带出去的是"打出来的"而不是"剩下的"

`applyRun` 入账的是 `run.earned`（`stats_total.materials` 的累计），
**不是** `run.materials`（结算时手里还剩多少）。

为什么这个区分是必须的：如果入账的是"剩下的"，
那么玩家**少买东西**就能多带钱出去 —— 于是局内商店变成一种"攒钱税"，
而"打得好不好"与"带出去多少"脱钩。用"打出来的"则相反：
买不买都不影响带出去的数，**商店花的是废料（局内那笔），材料照攒**。

这也正好满足用户那句"材料不该是在局内消费的"：材料在局内**只进不出**。

## 逐模块合规表（**进行中**）—— 六条判据 · 一份失败史 · 一条真实的架构张力

> 起因（上一轮留下的后半）："①（全项目逐项对'高内聚低耦合 + 数据表驱动 + 注册表 +
> 自检 + 测试 + 审计尺子'）只完成了一半……下一轮做这件事：先出'逐模块合规表'，
> 再挑扇出最重的那几处做有指纹兜底的重构。"

### 一、这一轮的产出：`pnpm run guards`

`tools/guard-gaps.mjs`。它回答两个问题，**只认两条能当场验证的判据**：

| 规则 | 判据 | 怎么验证 |
| --- | --- | --- |
| **A 模块自检** | 模块里有 `X.audit` **且** `SelfCheck.register` 登记了它 | 启动期真的会跑（`SelfCheck.names()`） |
| **B 跨表引用** | 别的模块的 `refs` 指向这个家族 | `Registry.audit()` 会去 `Registry.ids(目标家族)` 查那个值 ⇒ **写错就抛** |

```
65 个模块 · 103 个家族
守住的家族：86 / 103（自检 69 · 引用 13 · 两道都有 4）
提示级：没人守的家族 17 · 未被测试提到 0 · 有表没进总账 10
缺陷级：无参却未登记的启动期自检 0 ✔
```

**这 17 个没人守的家族，被降级成"提示"而不是"缺陷"** —— 这一步是本轮最重要的修正。
理由：家族只要**没人跨表引用**，`Registry.audit()` 本来就不查它，这**不一定是缺陷**。
给一张纯声明表硬加 `audit`，得到的往往是一堆同义反复（"这个值在这个表里"），
而真正要判的是"**值写错时有没有人喊**"，不是"有没有一个叫 audit 的函数"。
`setting`（改设置项名 → 项永远不生效）与 `scene` / `screenAct` / `overlay`（状态机接线）
本轮已经补上了真守卫，剩下的 17 个里最值得补的是
`dangerLevel` / `dangerMod`（修正键名 → 那条修正是假的）、
`particleKind` / `pickupKind` / `bulletKind`（贴图分派）、
`component` / `archetype`（组件原型）、
`challenge` / `challengeGroup` / `challengeMetric`、`depthBand` / `actor`、
`dailyField`、`scoreField`、`codexLevel`、`profileSection`、`offlineRate`。

**修法二选一**（写在工具输出里）：① 给声明它的模块写 `audit` 并登记；
② 让真正消费它的那张表用 `refs` 引用它 —— 那样 `Registry.audit` 就守住了。

### 二、这份工具写了五版，前四版都判错（这一段比结论值钱）

| 版本 | 做法 | 错在哪 |
| --- | --- | --- |
| 1 | 红线 = "有 `Registry.family` 却没 `X.audit`" | **9 个假阳** —— `Registry.audit()` 本来就在启动期守跨表引用 |
| 2 | 守卫限定成"属性名恰好叫 `.audit`" | **18 个假阳** —— `Comp.selfCheck` / `Scene.validate` / `Settings` 的守卫都不叫这名 |
| 3 | 用 family 的 `owner`**模块名**去匹配 `SelfCheck.names()` | **45/103 判错** —— 家族名与自检名不是一对一（`weapon` 家族 vs `Weapons` 自检） |
| 4 | 按"第一个参数是否为空"分"能进启动期 / 只能运行期" | **2 个假阳** —— `Emit.audit()` **无参**却读模块级会话 `S`；`Comp.selfCheck()` 无参却返回 `{duplicates, tracked}` 这种非约定形状 |
| 5（现行） | 只认上面那两条规则，且"能进启动期"要**三条结构事实**全中 | —— |

五版里四版是**同一个病**：**用文本形状或名字去猜运行时的语义。**
本项目此前已经记过四次"尺子漏了一整类"，这是同一类错误的第五次 ——
所以这一版**把不能证明的部分如实标成"读不到"，而不是猜一个 `✔` 或 `✘`**。

第 5 版把"能进启动期"从**一个签名条件**收紧成**三条结构事实**，每一条都能从源码当场读出：

| # | 事实 | 读法 | 反例 |
| --- | --- | --- | --- |
| ① | **无参** | 函数签名 | 必要但不充分 |
| ② | **返回 `{ok, problems}`** | 函数体里有 `ok:` 与 `problems:` | `Emit.audit()` 返回 `{duplicates, tracked}` |
| ③ | **无会话时能安全返回** | 函数体开头有 `if (!X) return` | `Emit.audit()` 直接读 `S.particles` |

②③ 这两条**不是吹毛求疵，而是登记进去会真的坏事**：

- 缺 ② 时，`SelfCheck.scan()` 只读 `r.ok`（`selfcheck.ts` 第 78 行 `if (!r || r.ok) continue`），
  于是 `{duplicates, tracked}` 里 `r.ok` 是 `undefined` ⇒ **登记一道永远绿灯的假门**，
  比不登记更坏。
- 缺 ③ 时，启动期 `S` 还是 `undefined`，一登记就抛，`scan` 把它 catch 成
  "自检本身抛了异常" —— 症状是"一启动就报一个看不懂的错"，而不是"守住了"。

工具的退出码也一并改诚实了：**以前无论报多少 ✘ 都 `exit 0`**，
于是"看退出码就当成通过"（本项目栽过好几次的那个坑）在这里必然复发。
现在 **缺陷级非 0 会真的让 `pnpm run guards` 变红**；提示级默认不拦，
要连提示级一起拦就用 `--strict`。这是刻意的：
**门只该拦"确凿的不一致"，不该拦"值得看一眼"。**

顺带纠正的两处（我一度写进输出、后来自己推翻）：
- `data_chars.ts` **有** audit（`C.audit` + `SelfCheck.register('Chars')`）——我一度报成"没有"
- `data_weapons.ts` 没有模块级 audit，但它的家族**被别的表引用**，所以并非"没人守"

### 三、一条真实的架构张力（**需要你拍板**）

**`Comp.selfCheck()` 是启动期不会跑的自检**：它验的是"36 个组件 / 11 个原型
逐字段齐全、默认值与模板一致"（写错一个默认值只能在这里抓到），
但它**只在 `test/comp.mjs` 里被调**，`SelfCheck` 里没有它。

> 第 5 版的工具**不再把它报成缺陷**了，理由是结构事实：它的返回值不满足
> `SelfCheck` 的 `{ok, problems}` 约定，登记进去只会得到一道**永远绿灯的假门**
> （`scan` 只读 `r.ok`，而它没有 `ok`）。也就是说，要接进启动期，
> 得先把它**改成**返回 `{ok, problems}` —— 这不是一处接线，是一次改写。
> 下面这一节记的仍是"要不要为此动架构约束"，请你拍板。

我试着把它接进启动期，被架构规则拦住了两次，两次都是**对的**：

1. 在 `comp.ts` 里 import `selfcheck.ts` → `组件层是纯声明与组合，只依赖 utils / 总账` 红。
   规则在 `test/ui-check.mjs` 第 97 行，白名单里只有 `utils` 与 `registry`。
2. 挪到 `main.ts` 的 `boot()` → 能跑，但 **`boot()` 只在 `DOMContentLoaded` 上执行**，
   而**测试路径根本不走 `boot()`**（没有测试提到过它）。
   于是那个自检会变成"只有真人打开游戏时才跑" —— 比放在测试里更糟。

**所以这不是我的疏忽，是一个设计上的二选一**（`scene.ts` 当初开了同一道口子，
白名单里给它加了 `selfcheck.ts`）：

- **选项 A**：把 `comp.ts` 的纯机制层白名单也加上 `selfcheck.ts`（与 `scene.ts` 一致）。
  代价：组件层从此可以注册启动期自检 —— 那条"只依赖 utils / 总账"的约束松一格。
  收益：36 个组件 / 11 个原型的字段完整性**每次启动都验**。
- **选项 B**：维持现状，把"组件表的守卫只在测试里跑"写进文档（现在这一段就是）。
  代价：**测试跑不到的那类错，启动期也拦不住** —— 而这类错恰好是
  "内联默认值写错"（NaN / 负零 / 科学计数法），只在编译期生成代码时才会出。
- **选项 C**：把 `Comp.selfCheck` 的调用点从 `test/comp.mjs` 挪进
  **`SelfCheck` 的注册表**（不改 `comp.ts` 的依赖，而是让 `selfcheck.ts` 反向拉一个
  注册钩子）—— 结构最干净，但`selfcheck.ts` 是层 0 的纯机制，
  它不该认识"有哪些模块想登记"。

**我的建议是 A**：`scene.ts` 已经证明了这条口子的代价可控（它同样是一张声明表），
而"默认值写错"这类错误的发现成本很高（它表现为某个组件字段莫名其妙是 NaN）。
但这条会动架构约束，所以我留给用户拍板，没有自己改。

给仓库补 `.github/`（CI + issue/PR 模板 + 协作文档）时，顺手盘了一次账，
发现三类**登记漂移** —— 东西在，但账上没有它：

| 漂移 | 症状 | 修法 |
| --- | --- | --- |
| `tools/score.mjs` / `draw-census.mjs` / **`yaml-check.mjs`** 存在但**没有 npm 脚本** | 写得再好也没人能调 —— 等于不存在 | 加脚本（`pnpm run score` / `draw` / `yaml`） |
| `test/arch.mjs` 在 49 套里跑，但**没有 `test:*` 脚本** | 想单独跑那一套时"命令不存在" | 加 `test:arch` |

第三条最值得记：那份旧工具报"**没人守的家族 4 个 · 硬性不合规 6 ✘**"，
而真实情况是 **0**（`guard-gaps` 的读数）。它的四条假阳恰好是
`guard-gaps` 文件头里**写清了的历史修正** —— `scene.ts` 那四个家族有
`Scene.validate` 守着，`registry.ts` 的守卫是 `SelfCheck.BUILTIN`（重复登记会抛）。
**一份会报假阳的旧工具比没有工具更坏**：它会让人照着不存在的问题去改。

**新增一把尺子：`tools/registry-drift.mjs`（`pnpm run drift`）。**

上面三类漂移有一个共同点：**它们不会让任何测试变红**，只会让下一个人多花半小时
找"那个工具怎么跑"。所以它值得一条能失败的判据：

```
A 每个 tools/*.mjs|cjs 要么有 npm 脚本、要么被别的文件 import
  （一次性迁移脚本单独登记在 ONE_SHOT 里 —— 它们的归宿是删掉，不是给脚本）
B 每个 test/*.mjs 要么在 run-all 的清单里、要么有 test:* 脚本
C 两个方向都对照：有脚本没进套件、进套件没脚本，都报出来
```

它第一次跑就抓到三个真问题（两个"没人能调"的工具 + 一个死调试脚本
`tools/_probe-ast.cjs`：15 行、零引用、功能已被 `curve-audit` 取代 → 删掉）。

**还有一个工具是自己被要求"自己写一个"的：`tools/yaml-check.mjs`（`pnpm run yaml`）。**

起因是补 CI 时本机**没有任何 YAML 解析器**（`node_modules` 与 python 都没有），
而项目是零运行时依赖的。更重要的理由是**"YAML 写错"在这里是一类真实故障**，
症状特别差：GitHub 只会说"workflow 无效"，或者更糟 —— **它安静地不跑**。

它做三件事：解析一个 YAML 子集（**不支持的语法显式报错，不做"尽力而为"**）、
按带 id 的规则校验、以及**自证**：自带一批"必须被拒"的坏 YAML 语料，
每次运行都先跑它们。于是"这把尺子还灵不灵"本身是可执行的判据 ——
而它立刻就有了回报：

> 我写规则时忘了声明**作用域**，于是 `workflow.top` 把 issue 模板也判成
> "顶层缺 `on:`/`jobs:`"（模板当然没有）。一个作用域没写清的规则会把自己的
> **假阳**当成真问题报出来，而"修"它的错误方式是把规则删掉。
> 现在每条规则必须写 `for: workflow | template | any`，且这条有测试守着。

独立验证：对**真实文件**注入 9 处错误（把 action 固定到 `@main`、删掉 `runs-on`、
把 `on:` 改名、去掉 `steps` 的 `- `、塞 TAB 缩进、模板项去掉 `type`、
把 `body:` 改名、顶层键重复…），**9/9 全被拒且报的原因都对**，还原后回到全绿。

## 游戏该有的东西（**已完成**）—— 验收盘 · 三个新系统 · 一条"有意不做"

> 起因："把一款游戏**该有的东西**补齐到'只差素材'的程度 —— 没有素材可以，
> 但必须有占位与可运行的系统（按实际盘点：音频/BGM 槽位、本地化与字体、设置项、
> 存档槽位、成就、教程、结算与统计、可访问性、暂停菜单、错误兜底、平台适配…）；
> 对实在难做或强行实现效果很差的，**不硬做**，把问题、代价与建议写进 README 留给用户决定。"

### 一、先做的不是功能，是**一张验收盘**

"该有的东西"如果靠记忆清点，一定会漏 —— 而且**漏掉的往往是刚做过的那些**
（人对自己刚写的东西有记忆优势，对三周前的没有）。所以这一轮的第一个产出是
`tools/game-kit.mjs`：27 项，每项都带**判据**（`KIT[].check`），跑一次就出清单。

```
pnpm run kit

共 27 项 · 已有 26 · 缺 0 · 有意不做 1
```

**这张盘第一次跑就暴露了一个比缺功能更值钱的问题：它把 3 项报成了"已有"，
而其中两项的证据是关键词撞词。** 尺子先于结论：

| 假阳 | 撞在哪 | 修法 |
| --- | --- | --- |
| "本地化已经有了" | `where('Locale')` 撞上 `String.localeCompare` | 判据改成"存在语言模块 + 一张语言表" |
| "成就已经有了" | `types.d.ts` 注释「图鉴里该列出来的」里有个"成"字 | 判据改成"代码里存在成就表"，并**不再扫 types.d.ts** |
| "性能守门已经有了" | 只找 `tools/*perf*`，而本作的性能尺子是 `test/perf.mjs` | 判据改成找测试文件 + 帧预算断言 |

第四处是**假阴**：`tutorial` 第一版找 `HINTS/TIPS` 与模块名，而实现叫
`tutorial.ts` 的 `LIST` + `pending(when)` —— "已经做了却报缺"。
**报假阳会让人以为做完了；报假阴会让人重做一遍已经有的东西。** 两种都要修。

### 二、补上的三个系统

#### 1. 本地化（`src/i18n.ts` + `tools/extract-ui-text.mjs`）

改造前是**零本地化**：中文直接写在 `index.html`（可见文本 111 条）与 `ui.ts` 的字面量里。
设计只有三条，每一条都是为了**不制造新的漂移来源**：

1. **以中文原文当键**（`I18n.t('开 始 游 戏')`）。为什么不另起 `menu.start` 之类的 id：
   那会多一层"id ↔ 文案"的映射要维护，而那份映射**没有真相** —— 改了文案忘了改 id，
   表现是"界面显示旧文案"。用原文当键时 `zh` 表可以**空着**（键就是它自己），
   于是"中文永远是对的"是**结构保证**，不是纪律。
2. **界面是唯一真相，表是它的产物**：`pnpm run ui-text` 从 `index.html` 与源码字面量里
   抽出所有可见中文，`--check` 负责**校对**（见下面的诚实口径）。
3. **缺键回退到原文**（也就是中文）而不是空白或键名本身。半翻译的界面里，
   一句中文远好过一句 `menu.start`；而缺了几条这件事由 `I18n.coverage()` 数出来。

**诚实口径（这一节的第一版是错的，改对了记在这里）**：`zh` 结构上 100%（键即原文），
`en` 是**部分覆盖**。

`--check` 的第一版报的是"界面里有、`MESSAGES.en` 里没有" ⇒ **2692 条**。
那个数字是假的有害数字：它把"**没翻译**"说成了"**缺键**"。
键就是中文原文、默认语言故意没有表，所以对 `zh` 而言**不存在"缺键"这个概念**
（`I18n.missingKeys('zh')` 正是因此明确返回 `[]`）。
现在把它拆成两个各自有名字的东西：

| 名称 | 含义 | 是不是缺陷 |
| --- | --- | --- |
| **待翻译存量** | 界面/源码里有、`MESSAGES.en` 里还没译文的条数 | ❌ 是工作清单，清到 0 才算翻完，但没清完不是 bug |
| **表中孤儿** | `MESSAGES.en` 里的键在界面和源码里**都不存在** | ✅ 真缺陷，非 0 退出 |

**为什么"表中孤儿"要单立一栏**：改文案时漏改表就会留下它，而它**比缺键更坏** ——
它会让人以为"那句已经翻译过了"。工具抽文案时原来有个 `{1,40}` 的字数上限
（"只收短串"），于是教程里那句 **41 个字**的
`血量过半了 —— 血到 0 就是这一局结束，但打到的材料会带出局（那是经营的本钱）`
抽不到自己，`--check` 反过来把表里**正确的**键报成孤儿。
上限删掉 —— 单引号已经天然隔离了边界，**长度不是安全属性**。

当前真实数字：界面与源码里带中文的文案 **2860** 条 · `MESSAGES.en` **73** 条 ·
表中孤儿 **0** 条 · 待翻译存量 **2787** 条（英文覆盖 **2.5%**）。

`test/i18n.mjs` **43 条断言**守着：切语言真的改 DOM、不认识的 id 被拒绝、语言名永远用母语写、
`data-i18n` 显式标键、缺键回退、与设置表接线。

#### 2. 存档槽位与搬运（`src/slots.ts` + `storage.ts` 的备份层）

三件事合成一个模块，因为它们回答同一个问题：**"这一份进度存在哪里"**。

- **3 个槽位**，实现上**只改键名不改数据形状**（`Storage.slotKey`）：
  0 号槽就是原来的键名，所以**老玩家的存档天然在 0 号槽**，不需要迁移链。
- **导出 / 导入**：一段 `BRNA1.<base64>.<校验和>` 的文本。
  为什么要有校验和：纯 base64 的文本**看起来都合法**，被聊天软件截断一段也照样能解出
  "半份存档"，而那种档导入之后表现是"金币变成 NaN"、报错只说"格式不对"。
- **崩溃安全**：每写一次留一份上一版（`key + '.bak'`），读坏了**自动回退并记一笔**
  （`Slots.lastRecovery()`），界面据此提示玩家"档坏过、已回退"，而不是静默少一半进度。

`test/slots.mjs` **60 条断言**。它抓到**两个真 bug**，两个都是"不报错、只是悄悄干错事"那一类：

| bug | 表现 | 真因 |
| --- | --- | --- |
| `Slots.writeJSON` 参数是"基键"却直接写下去 | **换槽位之后写永远落在同一个键上**；"切到 2 号槽"读到 0 号槽的档 | 读走 `Slots.readJSON`（它做槽位重定向）、写直接落盘 —— **两个方向的键变换必须成对** |
| `Storage.wipe()` 不清模块的内存副本 | "点了清空，数值还在"（`Profile` 的内存 `data` 还活着） | 删键之后**要通知持有副本的人重读**；现在 `Storage.onWipe` 是那条通道（谁持有谁订阅） |

还顺手修了一个**清档正确性**问题：只删主键的话 `readJSON` 会把备份写回去，
表现是"重置了但进度复活" —— 现在统一走 `Storage.removeAll`（主 + 备份）。

#### 3. 首局引导（`src/tutorial.ts`）

改造前上手只有一张静态的「操作说明」页：玩家在**真正需要提示的那一刻**
（第一波不知道要动、第一次进商店不知道能买、血少了不知道会掉什么）什么都看不到。

现在是一张**声明表** + 一个**时机判据**：8 条提示 × 8 个时机
（`run-start` / `first-wave-cleared` / `first-shop` / `first-levelup` / `low-hp` /
`first-boss` / `first-craft` / `first-meta`）。三条纪律：

1. **一条只说一次**（记在档案的 `tutorialSeen` 里，于是换设备/换槽位跟着那份档走）
2. **提示不是阻挡**：一条飘字，不暂停、不抢焦点、不挡按钮
3. **文案必须进 i18n 表** —— `Tutorial.audit()` 会拒绝"不在表里的提示"，
   否则切英文之后这几句一直是中文

`test/tutorial.mjs` **31 条断言**。它抓到一个**我自己刚写下的 bug**：
低血那条我挂在 `G.on('playerHurt', …)` 上 —— 而 **`playerHurt` 根本不是事件名**
（那是 `Emit.playerHurt` 粒子函数）。它不抛错、什么都不发生，
只是那条提示**永远不会出现**。抓到它的是 `test/signals.mjs` 那条
"没有'订阅了但永远不会触发'的死订阅" —— **又一次"尺子漏了一整类"的反面：这次尺子守住了。**

### 三、可访问性：两项设置，以及一次"空转开关"的自查

| 设置项 | 实现 | 一处值得记的教训 |
| --- | --- | --- |
| **色弱模式**（3 档） | `PAL.setMode` 换 canvas 侧的四个关键色（危险 / 治疗 / 经验 / 材料），换档时**连贴图缓存一起作废**；DOM 侧同步换 CSS 变量（`html[data-colourblind]`） | 只换 canvas 会出现"画面换了、按钮没换"，所以两处必须同时换 |
| **字号**（3 档） | `.layer{zoom: var(--ui-zoom)}`，缩放的是**界面层**不是 `#app` | ⚠ 第一版改的是 `documentElement.style.fontSize` —— 而这份 CSS 里尺寸**全是 px**（量过：`font-size` 68 处 px、**0 处 rem**），改根字号一个像素都不动。也就是说"字号"曾经是个**能存、能读、界面不变的空转开关**。现在用 `zoom`（它会连布局一起重排，所以按钮不会被放大后的文字撑破），并且缩放的是界面层、不动画面（画面分辨率由 dpr 决定，缩放它只会变糊） |

**"空转开关"这一类问题值得单独记**：它比"缺一个功能"更坏 ——
设置页上看得见、能点、能存、能读，**只有效果没有**。这一轮把它抓出来的方式很朴素：
**量一下这个开关该改的那个东西到底动没动**（数 CSS 单位）。

### 四、`○ 有意不做`：成就系统（**留给用户拍板**）

盘上唯一一条"有意不做"，理由与代价都写在盘上：

> **为什么不做**：本作已经有一张 29 条的**挑战表**（`challenges.ts`），
> 而它的每一条都给**内容解锁**（角色 / 武器 / 道具）。"成就"要补上的其实不是
> "再一张表"，而是"给纯里程碑发一个**徽章/称号**"这一层表现 ——
> 那是新的一屏界面 + 新的存档字段 + 新的文案量，
> 而它的作用（记录"你做过什么"）**战绩屏已经覆盖了大部分**。
> 在"只差素材"的验收口径下，多做一层会与挑战表**职责重叠**：
> 两条都在回答"我打到过什么"，玩家会分不清该看哪一个。
>
> **真要做的话**：约 300~500 行（表 + 存档 + 一屏界面 + i18n 文案）+ 一屏 UI 的截图回归。

**这一栏是这张盘最重要的一栏**：一份只会喊"缺"的清单会把人逼去做那些
**做了反而更差**的东西。所以盘把"缺"与"有意不做"分开报，而且后者必须带着理由与代价。

### 一、`reconcile`：把"声明了却没人用"从**猜**变成**数**

这个项目有十几张声明表，每张都有 `audit()`。但 `audit()` 只能证明**表内部自洽**，
回答不了"这些声明运行时有没有人真的在用它"。已有的三把尺子各管一段：
`data-contract` 查"数据表字段有没有家族守"（表 → 表）、`arch-audit [9]` 查
"声明了却没人按名字引用"（**文本近似**）、覆盖率查"哪些函数没跑过"（工具层）。
缺的正是**中间那一段**：一张表的条目 → 它在运行时被读了几次。

做法：跑一局真实的游戏 + 把渲染 / 音乐 / 结算 / 局外消费四条生命周期各驱动一遍，
把每张表的"读出口"包一层计数器，然后逐条对照。

```
八张表合计：109 / 137 条在运行时被读到（80%）
出口被整个漏掉的表：没有 ✔
```

**这张表的价值不在于那个 80%，而在于它把三种完全不同的"0"分开了** ——
而第一版把它们全报成"没人用"，那是在冤枉代码：

| 那个"没读到"其实是 | 例子 | 处理 |
| --- | --- | --- |
| **尺子没接上** | `Challenges.valueOf` 遮蔽了 `Object.prototype.valueOf`；`Eco.edge/byTier` 全仓只有 `audit()` 在调，运行时根本不查那张表 | 换到**真正的**读点：挑战改看挑战表自己的 `metric` 字段；货币改看"账有没有被读写"（`Profile.spores/alloy/core` + 局内买卖 + 据点/图纸消费） |
| **冷路径没驱动到** | 死人不在了 → 场上 0 只怪 → 白闪/精英两条贴图路径一次都进不去；据点已满级 → `canBuy` 永远走"已经满级"那一支，**核心材料的读点碰不到** | 显式驱动：现造一只精英怪（走 `spawnEnemy` 正规入口）；先买满再补跑"带核心门槛"的那一轮 |
| **开机读一次，之后折成常量** | `game.ts` 顶部的 `ELITE_HP/DMG/SPEED` 与 `LEVELUP_CARDS` —— 模块加载时就 `Curves.at(...)` 读掉了 | 单独归一类报出来（并且**静态确认**那四个读点真的在源码里），既不算"运行时在读"，也不冤枉成死数据 |

### 二、内部参考逮到的三个真问题

#### 1. 三个"只涨不花"的死写入器（与 `spendCore` 是同一类）

`profile.ts` 里有三个公开写入器：`addAlloy` / `addCore` / `addSpores`。
第 403 行那段注释上一轮刚写过"`spendCore` 定义着但没有任何调用点"，
**而这三个是同一类东西，当时没被一起清掉**：

| 函数 | 定义 | 全仓调用点 |
| --- | --- | --- |
| `Profile.addCore` | `profile.ts:404` | **只有测试**（`test/forge.mjs` / `test/keep.mjs`） |
| `Profile.addAlloy` | `profile.ts:387` | **只有测试**（`test/forge.mjs`） |
| `Profile.addSpores` | `profile.ts:454` | **只有测试**（5 个测试文件） |

真正的入账路径是 `applyRun` 直接写 `data.core +=` / `data.alloy +=` / `data.spores +=`，
消费路径是 `keepBuy` / `forgeNode` 直接减。也就是说这三个函数在**运行时一次都没被调用**。

为什么留着（而不是像 `spendCore` 那样删掉）：它们是**唯一**的"合规加钱"入口，
测试靠它们给资源。但"运行时没用"这件事必须写下来 ——
否则下一个人会以为"加钱走 `addSpores`"（那不是事实），
而这类误解的表现是"钱对不上"且查不出来。**这是一条待拍板项，见文末。**

#### 2. `player.cardGain` 是**第二个出处**

`curves.ts` 里有一条曲线叫 `player.cardGain`（"属性/张"，`exponential {a:1,r:1}` = 恒为 1），
注释写着"玩家每级长多少的一半答案在它这里"。而运行时是 `game.ts:39` 的 `var LEVELUP_CARDS = 4;`
—— **表是摆设**，改表不会有任何效果。这正是本项目反复在拆的"同一件事的第二处出处"。

改法：`var LEVELUP_CARDS = 4 * Curves.at('player.cardGain', 1);`
（模块加载时读一次并缓存，与 `ELITE_*` 同一处理；值恒为 4，所以**行为指纹逐位不变**）。

#### 3. `challengeMetric` 表比内容宽：25 / 35 个指标名没有任何挑战用

`[7]` 那一节第一版报"13/35 被求过值"，看着像表烂了。按挑战表自己的 `metric` 字段数一遍，
真相是三层：

| 层 | 个数 | 含义 |
| --- | --- | --- |
| 驱动着挑战 | **13** | 这条度量真的决定一条挑战成不成立 |
| 有采样点但没挑战用 | **6** | `main.ts` 的 `samplePeaks` 每波都在算（`maxEngineering` / `maxRangedDmg` / `maxElementalDmg` / `maxMeleeDmg` / `maxRange` / `maxHp`）—— **内容余量**，加一条挑战就能用 |
| 没采样点也没挑战用 | **16** | `runs` / `wins` / `bestWave` / `bestKills` / `bestLevel` / `level` / `kills` / `materials` / `damage` / `taken` / `healed` / `charRuns` / `charKills` / `charWins` / `storyFragments` / `storyFloor` |

后两层都**不是 bug**：`Challenges.context` 会把 35 个名字全部摊平进 `flat`（所以"读到"对整张表都成立），
真正的含义是"**表比内容宽**"。这个项目里"机制在、数据空"一直是允许的
（`Eco.GAPS = []` 那节就是同一个道理）；把余量当成死数据删掉，
下次加挑战就要重新接一遍线。**这是第二条待拍板项：要不要为这 22 个指标补挑战。**

### 四、多维度的两张矩阵表（`pnpm run matrix`）

`fun-audit` 报的是**一批随机局的中位数**（"典型体验"）；
它答不了"哪个角色被落下了""难度梯子是阶梯还是墙"。
`matrix` 按维度跑，并且**同一个 `runIndex` 在不同格子里是同一个世界**（地图/商店/出怪都一样），
差异只来自角色与难度 —— 于是可以逐列对比。

五节：`[1] 角色维度`（9 角色）、`[2] 难度维度`（D0~D9 单调性）、
`[3] 波次维度`（**内部曲线**与**实机落点**对齐在同一行）、
`[4] 内容维度`（上过货架 → 被买走 → 活到终局，三级漏斗）、
`[5] 循环维度`（三笔钱的产出与零核心局比例）。

`[4]` 的数据走**事件总线**（`market.ts` 只发事件，界面自己去订阅）——
于是"工具看到的"与"界面看到的"是同一批事实，而不是工具去翻内部字段后再猜一遍。

三件事：

1. **角色倍差 9×**（工程师 36 波 vs 受虐狂 4 波）。这不是"随机波动"：
   受虐狂中位 **4 波 / 33 击杀 / Lv4**，法师 **6 波 / 71 击杀 / Lv5**，
   而前四个角色都在 **35~36 波**。
2. **难度不是一个数字，而是十种不同的改动**：D1/D2 只抬怪血、D4 抬精英率、
   D5 抬物价、D6 收紧房间时限、D7 抬伤害与移速、D8 把后期怪提前 + Boss 更频繁、
   D9 双 Boss + 开局 85% 血 + 货架少一件。
   实测 D0→D9 的中位波次只差 **5 波**（38 → 33），而 **D6 与 D8 各自掉得更深**
   （D6 掉到 25、D8 掉到 16，通关率 33% / 21%）——
   也就是说**"难度靠改结构而不是靠加数字"这条设计真的生效了**：
   真正劝退玩家的是"时限更紧"与"后期怪提前出场"，不是"怪更厚"。
   代价是"波次随难度平滑下降"这个期待本来就不成立（D9 的 33 高于 D8 的 16，
   因为 D9 加的是"双 Boss"这种**质**的变化，而波次这个指标看不清质变）。
3. **合成是空的**：284 局里 `rec.crafted` 有数据之后仍然接近 0 ——
   也就是说 **"合成树"这条边在 bot 的对局里没被走到**，合金几乎全部来自"回收装备"。
   这是"bot 不做长线规划"的局限，但也说明合成树对玩家的**必要性**没有被压力测试过。

### 五、这一轮补上的两处"尺子自身的 bug"（比游戏 bug 更值得写下来）

| 现象 | 真正的原因 | 修法 |
| --- | --- | --- |
| 漏斗第二级恒为 0（"被买走 0 件"，而终局装备表明 55 件全被用过） | 事件里带的是**中文显示名**（`emit('buy', { name: o.def.name })`），工具拿它当 id 去查表 | 建 名字→id 对照表（`NAME2ID`），买 / 卖 / 包开出来的东西都过它 |
| `--shard 1 --of 8` 跑出 **0 局**（不是慢，是空） | 分片哈希只用 `dim|key`，同一个角色的 8 个种子哈希相同 → 全落在同一片或全落空 | 哈希输入加上种子序号；`runIndex` 也改成由 `(维度,键,种子)` 推导，**与分片数无关**（第一版 `base + s*1000` 让"分 24 片"和"分 12 片"采到不同的世界，还重复采样了 ranger） |
| 「实测怪血」一列全是 `—` | 采样器挂在 `waveStart` 上，那一刻怪还没生成 | 改挂"玩家可操作的每一帧"（`_run.mjs` 新开 `setRunTick` 钩子），按波节流 |
| 第 10~39 波的「玩家等级」全是同一个数 | 用**终局数值**回头填"到第 N 波时什么水平"，而那批局的终局在更深处 | 改成**当场记**：每一波的第一帧就写快照 |

**这四条没有一条是游戏的 bug，但它们都会让结论反过来**：
前两条把"玩家明明买了"报成"没人买"、把"很慢"报成"没数据"；
后两条把"玩家到第 10 波就不长了"这个假象造出来。
所以修完之后我又重跑了一遍 —— 这也是"矩阵体检"这一节的所有数字的来源。

### 六、一次可检验的对照：低血机制被 bot 的打法盖住了

`fun-audit` 的 bot **见血就补**（低于 30% 上限就回满）。
对「受虐狂」来说这是致命的：它的 `rage` 机制要求**血低**才生效
（`game.ts` 的 `recalcStats`：`damage += rage*0.30`，`rage` 由缺失血量算）。
一直补血 = 永远在玩一个白板受虐狂。

所以给 `_run.mjs` 加了 `noHeal`（门槛 30% → 10%）并做了一次 A/B：

| 角色 | 正常打法（6 局波次） | `noHeal` |
| --- | --- | --- |
| 受虐狂 | 2 · 3 · 3 · 8 · 8 · 26 | 2 · 2 · 2 · 3 · 3 · 4 |
| 元素法师 | 5 · 8 · 8 · 9 · 26 · 26 | 2 · 2 · 2 · 3 · 3 · 4 |
| 工程师 | 8 · 16 · 18 · 19 · 23 · 26 | 2 · 3 · 4 · 4 · 4 · 16 |

**`noHeal` 对三个角色都更差** —— 于是"见血就补把受虐狂盖住了"这个假设**被证伪**。
但这一轮对照仍然值钱：它把"角色弱"与"bot 打法不合"分开了。
现在剩下的解释只有一个方向：**这两个角色的开局身位太薄** ——
受虐狂 `maxHp −8`（20 → 12）、`armor −2`，第 2~3 波只要三下就没了，
而它的收益（rage）要到低血才兑现。
**这是设计问题，不是 bug，所以我没有动它** —— 见文末待拍板项。

### 十、诚实记下来的剩余问题（**待你拍板**）

1. **三个"只涨不花"的写入器**（`Profile.addAlloy/addCore/addSpores`）：
   运行时零调用，只有测试在用。
   *选项*：(a) 删掉，测试改成直接调 `applyRun` / `pickSpores` 之类的语义入口；
   (b) 留着并在 `types.d.ts` 里标明"测试专用"；
   (c) 把运行时那三处 `data.x +=` 改成调它们（真正的"单一入账口"）。
   **代价**：(a) 要动 5 个测试文件（低风险、但会把"给资源"这件事打散到各处）；
   (c) 最干净，但会把 `applyRun` 里那三行"顺手加"变成一次函数调用（无行为变化）。
2. **22 个没有被任何挑战用到的指标**（6 个有采样点 + 16 个纯余量）。
   *选项*：(a) 维持现状（余量，允许）；(b) 为它们补挑战（**这是内容工作量，不是重构**，
   而且会改动解锁曲线 —— 会动到难度与节奏，我不该替你决定）。
3. **两个角色的开局身位**（受虐狂 / 元素法师）。数据：
   受虐狂中位 **4 波**、法师 **6 波**，而工程师/角斗士/掘进者 35~36 波；
   `noHeal` 对照证明**不是** bot 打法盖住了低血机制（换了打法反而更差）。
   它们的设计意图都成立（极限 / 玻璃炮），但**代价那一半来得比收益那一半早**：
   受虐狂 12 血 0 甲在第 2~3 波三下就没了，而 rage 要低血才兑现。
   *选项*：(a) 保持现状（"难上手"本身是设计）；(b) 把代价挪后一点
   （例如受虐狂 `maxHp −8 → −4`，或开局给一层护盾/吸血）；
   (c) 把收益提前（rage 从"缺失血量"改成"最近 3 秒受过伤"）。
   **这会改动难度与手感，我不该替你决定**。
4. **合成树在 bot 的对局里几乎没被走到**（284 局里接近 0 次合成）。
   bot 不做长线规划，所以这既是 bot 的局限，也说明那条边**没有被压力测试过**。
   要验证它值得做，需要一个"会攒料、会看配方"的 bot（或人类测试）。
5. **`dungeonStructure` 瓦片集没有运行时读点**：战场外墙仍是 `drawBounds` 的四个矩形。
   接上它 = 战场外观改造（美术决策，不是 bug）。
6. **5 条备用 shader**（`outline` / `dissolve` / `hologram` / `chroma` / `maskReveal`）：
   机制在、没接线，`art-audit` 允许"登记为备用"。
7. **42% 通关率仍是 bot 的数字**，不是人的。要判断难度得人类测试。
8. **矩阵体检很贵**：一次完整的角色维度（9 角色 × 8 种子，40 波上限）
   在 16 核上跑并行也要**半小时以上**。所以默认用 `--seeds 4`，
   要更高分辨率时加 `--seeds 8 --maxWave 25`（波次上限压到 25 能省一半时间，
   代价是看不出"能打穿 25 波以上的角色到底能走多远"）。
9. **元进度的"抑制项占比"没有量过**。外部参考给了两个可用锚点
   （VS 的费用项占总成本 **90.9%**、Hades 满树 **35,365 Darkness**），
   而本作只量到"每局带出孢子中位 517"。
   要回答"一棵树要多少局"需要把 `Talent` 的逐级成本求和，
   再除以单局产出 —— **这一步没做，所以"元进度节奏合不合理"目前只有定性判断**。
10. **同屏敌人上限没有硬顶**（Brotato 是 100）。探针实测峰值 ~300 而性能仍有余量
    （300 怪 0.594ms/步），但**"300 个怪还看得清吗"没量过** ——
    那需要人类盲测（外部参考里那条"100 敌人同屏辨认正确率 ≥ 80%"就是这个用途）。
11. **`docs/external-benchmarks.md` 是调研原文**，不是本作的结论。
    它的价值是"每个数字都能追到出处"，读它时请连同标注一起读 ——
    `[摘要]` 与 `[实取]` 的可信度差一个量级。
