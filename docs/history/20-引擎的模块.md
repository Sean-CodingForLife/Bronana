# 20 · 引擎的模块（功能单元）

**用户口径**（规范 [`workspace-spec.md`](../workspace-spec.md) §一 / D-004）：
「引擎自己就是**一堆模块**，插件与原生模块**走同一套加载器**，每个工作区各自声明开关。」

---

## 一、这一轮落地了什么（以及**没有**落地什么）

| 件 | 落点 |
| --- | --- |
| 9 个引擎模块 + 各自的依赖（`requires` 向下 · `alsoNeeds` 例外） | `src/module.ts`（四步齐全） |
| 依赖**拓扑序**（不是 import 顺序；同层按 id ⇒ 顺序**确定**） | `Module.order()` |
| **被禁用的模块不得被任何启用的模块依赖** | `Module.check()` · 门 `workspace` · `test/arch.mjs [7]` |
| 命令面 `module list` / `module why <id>` | `src/cli.ts`（规范 §六 里那两条只读命令） |
| ❌ `module enable\|disable` | **刻意没做**：它们要写清单，属批次 ⑤；先做一半就是"假开关" |
| ❌ **动态装载器**（按清单只 import 被启用的模块） | **还没有** —— 今天开关的效果是**判据**，不是装载。要它得先按模块切目录 |

**说清楚这一条**：宿主今天仍然是静态 import 全部（`cli.ts` 的 `registry: 'partial'` 那种手写例外
就是它的替代品）。**不许**把"判据落地"讲成"装载器做完了"——
两者的差别正是本仓库最忌的那种"看着都有、其实少一半"。

## 二、三条判据，两个视角，一条真话

同一个事实有**两张表**，而它们谁也读不到谁：

| 视角 | 住在哪 | 回答什么 |
| --- | --- | --- |
| **审计视角** | `tools/systems.cjs`（9 系统 · 层号 · 例外清单） | "依赖方向对不对" |
| **引擎视角** | `src/module.ts`（模块 + 依赖） | "引擎由哪几块组成、起来要谁" |

`src/` 不许 import `tools/`（那是宿主侧的东西）⇒ 只能**对账**。
`test/arch.mjs` 第 [7] 节拿**真实 import 图**当裁判，四条判据（都注入坏数据证明会红）：

1. 两张表的 id 集合**完全相同**（两个方向）；
2. `requires` 全部指向**严格更低层**；`alsoNeeds` 全部指向**严格更高层**（"例外"的定义）；
3. **真实直接依赖 == `requires` ∪ `alsoNeeds`**（逐模块相等 —— 声明不许漏，也不许多）；
4. 向上的真实边**逐条**登记在 `EXCEPTIONS` 里（与门 `audit` 那条纪律同一个出处）。

写这份表之前**先量了真实图**（临时脚本从 `analyze()` 的 `A.systems.edges` 算出来），
所以 (3) 是**一次就过**的 —— 这不是运气，是"先量后写"。

## 三、这一轮最值钱的一条发现：**真实图在系统级有环**

第一次给 `data` 写上 `alsoNeeds: ['meta']`（那条例外是真的：`enemies.ts → danger.ts`）之后，
`Module.audit()` 当场报**拓扑序排不满**：

```
模块依赖成环，环上（或指向环）的模块：data / dungeon / meta / sim / art / run / view / boot
```

这不是"发现了一个环"，而是**我把两层事实混成了一层**：

- `requires` = **层关系**（向下，天然无环）⇒ 它决定**顺序**；
- `alsoNeeds` = **例外的真实依赖**（可能向上）⇒ 它只决定"**能不能禁用**"。

`tools/systems.cjs` 用的模型本来就是「**层号 + 例外清单**」而不是纯 DAG ——
模块表跟着它分成两种关系之后，`order()` 只认 `requires`，判据立刻全绿。
**如果当时选的是"给环开个豁免"，那就是把模型改坏了去迁就实现。**

## 四、顺手对齐的一处**用词**（同一个词的两层含义）

`AGENTS.md` 的术语纪律写着"**模块** = 用户定义游戏机制与玩法的方式（战斗 / 经营 / 养成）"，
而 `workspace-spec.md` §一 用的是"**模块** = 引擎的功能单元" —— **同一个词，两层含义**。

处置不是改词，而是**把两层关系说死**（两边各加一句）：本节的"模块"是**上位词**
（引擎原生 / 插件 / 内容侧的都算），那一节的"模块"是**内容侧**的那一类；
写的时候**带限定词**（「引擎模块」/「玩法模块」）。⚠ 这类冲突**只写在文档里没用** ——
所以它同时写进了 `src/module.ts` 的头注释（读代码的人先看到它）。

## 五、自曝的一个错：**先猜后量**

改文档数字时我把 `src/` 的行数写成"47278 行"（**猜的**），
而 `node tools/readme-stats.cjs` 一跑就是 **46584 行** —— 差 694 行。
数字只在**一处**（`readme-stats` 的输出）是真相，**先跑一次再写**是唯一正确的顺序；
这一条家法（"数量一律从清单算"）说的就是这个，而我还是先写了。
