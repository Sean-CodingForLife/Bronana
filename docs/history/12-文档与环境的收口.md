## 一、体积判据：从"贴着今天"改成"按最终体量的容量规划"

**用户的口径**：「我这个项目的体量只会不断地增长，应该**直接先预判最终大小**再去检查和重新设置」。

- `chunkSizeWarningLimit` 760 → **50000**（改成**事故探测器**：抓解析失控 + **gzip 看不见的可压缩巨物**）。
- 产品判据（**玩家真正下载的那一份**）改成：gzip JS ≤ **3 MB** · 全站 gzip ≤ **4 MB**（今天 282.2 / 298.2 kB）。
- **同时查出一个洞**：那条判据读 `dist/`（构建产物），而 `pnpm verify` **不重建它** ⇒
  **本地量旧包恒绿、CI 量新包恒红**。实测：**CI 从 #51 起连红 8 轮**而本地一路"全绿"。
  已修成"**判据自己保证新鲜**"（产物旧了先构建一次）。
  ⇒ **判据的结论不许取决于一个陈旧产物。**

## 三、环境那一层：`env` 门 + 机器层三层

**用户点出的一问**：「这个仓库**不一定是固定机器上开发的**，所以**本机到底指哪台**，要说清楚」
＋「这是 Node 项目，不是有类似 `.env` 的文件么」。

- **补掉一个真实泄漏口**：`.gitignore` 里**原本没有 `.env`** ⇒ 谁建一个就会被 `git add -A` 带进版本库。
- **`.env.example`**（键的声明）+ **门 `env`**（读点 ↔ 声明表**双向**对账）：
  它当场抓出 **10 个从没被声明过的键**。自证：`--self-test` 注入假读点 ⇒ 红。
- **`tools/where.mjs`（环境事实卡）**：机器身份 + 每个键的值**与来源** + github 代理配没配。
- **三条实测结论**：① Node 24 原生 `--env-file` ⇒ **零依赖**（不加 dotenv）；
  ② 🔴 **`--env-file` 不覆盖 shell 里已有的同名变量**（"我改了 `.env` 怎么不生效"是**结构性**的）；
  ③ 可选文件必须用 `-if-exists`。
- **三层表**（`AGENTS.md` §三）：仓库层（`.env.example`）/ 机器层（`.env` + `~/.gitconfig`）/ 会话层（`.session.json`）。
  判据：**环境须知里的每一句都必须能回答"在哪台机器上"**。

### 附属：一条把 AI 卡了十几轮的机器陷阱

`git`（libcurl）**不读 Windows 的 WinINET 代理**。这台机器（`DESKTOP-9R11UOR`）系统代理开着
（`127.0.0.1:7890`），于是 git 一直**直连** `github.com` ⇒ `reset` / 21 秒超时 / 403。
判据：**`git ls-remote` 也失败**（连读都不通）⇒ 是传输问题，**不是权限**。
修法一行（`http.https://github.com.proxy`），**端口号刻意不写进文档**（那是机器层的值）。

> 我在这条上一次误判（先说成"只读 token 被 git 用上了"，其实 git 的凭据库里**根本没有账号**），
> 更正的过程记在这里，免得下一个人重走：**先量"读"能不能通，再谈权限。**

## 五、文档状态机 + 链接门（本仓库"文档会自己说话"的收口）

- **门 `doc-front` 扩成状态机**：`status` 必填（`草案/现行/已取代/已作废`）·
  **`已取代` ⇒ 必须写 `superseded-by` 且目标存在**（抄 PEP 1 的双向指针）·
  **不是"现行"的 ⇒ 必须有可见横幅**（抄 boxer）。33 份文档补了 `status`；
  一次性脚本默认写成"现行"，**当场抓出一份错标**（`techstack-upgrade-research.md` 应为「已取代」）。
  ⚠ **刻意没加 `last-reviewed`**：给 33 份填复核日期而大多数我没真复核 —— 那与 `owner` 被否掉同理。
- **门 `doc-links`（第 27 道）**：① 仓库内链接必须解析到存在文件（170 条）；
  ② **`docs/README.md` 索引与盘上两个方向都对得上**（孤儿文档 / 指向空处的索引项）。
  **不查外链**（受限沙箱里联网检查会因 DNS 假红）。自证：注入一份坏链接的探针 ⇒ **两条判据同时红**。
