## 二、本批做了什么（批次 1：清单先落地，再搬东西）

**顺序理由**：E4 是 `git mv`（**不可逆**）。动 41 个模块之前，先让"**一个工作区是什么**"
有一个**唯一的、可校验的出处** —— 否则搬完没人能回答"搬对了吗"。

1. **`workspace/Bronana/teapot.workspace.json`**（第一份真清单）：`schema` / `id` / `displayName`
   / `engine` / `entry` / `storage.namespace` / `modules` / `plugins` / `content` / `note`。
   ⚠ 它**如实写着过渡状态**：`entry` 与 `content.src` 今天还指向仓库根的 `src/`（批次 3 才搬）。
2. **`src/workspace.ts`** —— 引擎侧**纯函数**校验器（坐 L0，理由是它只 import registry/selfcheck，
   而且**不读盘**：`src/` 不许碰 Node，那是"67 套测试能在 Node 里跑"的前提）。四步齐全：
   声明表 `FIELDS` · `Registry.family('workspace')` · `SelfCheck.register('workspace')` · 纯 `parse`。
3. **门 `workspace`（第 28 道）** —— 三条判据 + 四条自证。
   **关键设计**：门**不自己写一套校验**，它 `import ../src/workspace.ts` 的 `Workspace.parse` ——
   同一个判据两份实现迟早漂开（`systems.cjs` 的头注释写着同一句话）。
4. 门数级联 27 → **28**，模块数 97 → **98**（`doc-num` 当场指出 AGENTS 与 requirements 两处）。

## 三、三条判据（都抄自真实的坑，出处见 `docs/workspace-spec.md` §四）

| 判据 | 抄自 |
| --- | --- |
| **未知字段 = 报错**（不许静默忽略） | Cargo：`workspace.metadata` 官方原文是 "ignored by Cargo and **will not be warned about**" |
| **缺必填 = 报错** | pnpm 官方自认的最坏失败："**silently link no project at all**" |
| **`storage.namespace` 必须等于 `id`** | Godot 的反面教材：它的 `config/name` **同时**决定 user data 目录 ⇒ **改名 = 存档搬家**。成因只是**复用了一个字段** |
| `schema` 不认识就停下 | Godot：`config_version` 更高的项目在项目管理器里**置灰**，而不是"尽力打开" |

外加两条**提示级**（不判红）：目录名与 `id` 不一致（规范说"目录名不参与身份"，但它常是"改名改了一半"）、
以及输出的清单总表（目录 / id / displayName / 结论）。

**自证**（家法）：`--self-test` 注入四份内存里的坏清单（未知字段 / 缺必填 / namespace≠id /
schema 不认识），**四条逐条确认会红**，退出码 0 只在四条都红时给出。

## 四、⚠ 本批踩的两个坑（都值得记）

1. **我在块注释里写了 `workspace` 加一个星号加斜杠的路径通配**（想写「每份 `workspace/<星>/teapot.workspace.json`」）——
   那两个字符 `*` 与 `/` 紧挨着，**把块注释提前关掉**了，于是下面几行落到代码位置 ⇒ `SyntaxError`。
   **这正是 `AGENTS.md` §八 记录的第 7 类失败，而且那节写的就是"本项目在写 `dev-edit.mjs` 的文件头时真踩过"** ——
   我读着它又踩了一次。⇒ 已改成 `<目录>`。
   **教训：这条规则不是"知道就行"，它需要一条判据**（见卷末欠账）。
2. **`insertBefore` 把锚点行复制了一份**：我的插入文本结尾写了 `    id: 'doc-links',`，
   而锚点行本身就是那一行 ⇒ `doc-links` 在 `GATES` 里出现**两次**。
   后果很有意思：**`verify --list` 说 28 条，而 `doc-num` 说 29 道** —— 两个判据对不上。
   查出来是"同一个 id 出现两次、`--list` 按 id 去重而 `doc-num` 按出现次数数"。
   **教训：插入文本**不要**包含锚点行本身**；而且"两个判据给出不同的数"必须当场查清楚，
   不许挑一个信。
