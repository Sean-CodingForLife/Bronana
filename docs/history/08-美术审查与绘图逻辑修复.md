## 一、审查怎么做的（可复现）

1. **读代码**：`art_spec.ts`（美术规范 / 六道工序 / 预算）、`draw2d.ts`（美术宪法执行层）、
   `sprites.ts`（造型总库）、`bronana.ts` + `appearance.ts`（角色与外观）、

   `art_shaders.ts`、`data_items.ts` / `data_weapons.ts` / `data_chars.ts` / `enemies.ts`。

   `draw-census`。
3. **量**：用一个临时脚本把"声明表 ↔ 画法 `case` ↔ 数据表"三者逐名对账，

瓦片 mask 位序与 `art_tiles.ts` 同序）；真正的洞在**颜色宪法无人守**

与若干条**绘制缺陷**。

## 二、第 1 轮：修掉"肉眼可见 + 根因清楚"的四条

### 1. 精英怪拖着一块金矩形（最重的一条）

- **表现**：探针实测 —— 世界画布上出现 **1 次 `PAL.GOLD`、alpha 0.3 的 90×86 实心 `fillRect`**，
  设备空间左上角 `(1100,629)` 正好落在怪的身体中心，而同帧该怪的贴图中心是 `(1099,637)`。
- **根因**：`render.ts` 在**世界画布**上直接执行 `elite` shader，而它的步骤是
  `op: 'add'`（= `lighter`）＋ 执行器的 `fillRect(0,0,W,H)`：
  既不认目标 alpha，用的又是当前变换原点（不是贴图盒）。
  `sprites.ts` 与 `art_shaders.ts` 的注释却都写着"精确地只落在怪物轮廓内"。
- **改法**：把覆盖层**烘到贴图上再 blit**（与白闪同一条路）——
  `sprites.ts` 新增 `bakeOverlay(prefix, def, shaderId, params)`，白闪与精英色各自一行；
  `elite` 的合成步骤改回它**自己声明的** `atop`（认目标 alpha，于是只落在剪影内）。
- **改后实测**：世界画布上的金色 `fillRect` **0 次**；最靠右的两次 blit
  `(1056,593) 88×88` 完全同落点（本体 + 覆盖层）；缓存键 `el-grub`。

### 2. 姿态图集缓存键不含皮肤颜色

- **表现**：同一（职业 / seed / 脸型 / 情绪 / 眼型 / 斑点 / 呼吸档）换皮肤 →
  探针实测拿到的是**同一个 `canvas`**；贴图里旧色 `#111111` 有 9 笔、新色 `#22ff22` **0 笔**。
- **后果**：两个存档同职业不同色板时，身体沿用上一套色，而手臂（逐帧矢量）与肖像
  （键含 `look`）是新色 —— 同一个角色身上两种颜色。
- **改法**：键尾追加 `skinKey(opts.skin)`（base/hi/sh/dp 四段，`undefined` 落成固定占位符）；
  `render.ts` 的预热判据从布尔量改成**指纹**（职业 + 四色 + 脸型 + 半径），
  否则新色板的第一帧会现烘约 25 张（正是预热要消除的抖动）。
- **改后实测**：换皮肤 → 不同 `canvas`，各自只有自己的颜色（9 笔）；
  同皮肤再取 → 命中同一张；`skin: null` 两次同键。

### 3. `D.eye` 没有 `'none'` 分支

- **表现**：`draw2d.ts` 的分派只有 `round/dot`、`angry`、`dead`、`else`（= `stern`），
  而 `sprites.ts` 对 `shape === 'eye'` 传的正是 `'none'`（那里的注释写着"眼球本体已有瞳孔"）。
  于是浮游之眼 / 钟摆的白眼球上多压一道半月形。
- **改法**：补 `'none'` 真分支（一笔不画）并写清它与选项常量 `D.O.none` 的区别；
  顺手把 `enemyEye` 家族里**从来没有过画法**的 `empty` 删掉（它是 `D.O.empty` 被误当成眼型）。
- **改后实测**：`none` → `fill=0 stroke=0`；`orbiter` 贴图里 `PAL.INK` 填充从 2 笔降到 **1 笔**
  （只剩瞳孔）。

### 4. 磁铁图标 5 笔死绘制、tint 完全不可见

- **表现**：`:1027` 的 tint 弧被 `:1028` **同几何同线宽(13)** 的 `PAL.INK` 弧完整盖住；
  `:1032-1033` 的两块红极头被 `:1034-1035` 同几何的 tint 块盖住。
  实测该图标线宽集 `{13,7,2}` —— 是 21 个图标里**唯一没有 3px 墨线**的（其余 20 个都是 `{3}`）。
- **改法**：保留 tint 本体（13px 带宽），把墨线挪到内 / 外边缘（各 3px），两极分红蓝。
- **改后实测**：线宽集 `{2,3,13}`、**同几何重合组 0**、tint 笔画 13px 存在。

## 四、这一轮踩到的坑：并行会话把未提交的改动整文件冲掉

- **现象**：第 1 轮改完并通过目标套件后，`git diff HEAD --numstat` 显示
  `sprites.ts` / `draw2d.ts` / `art_shaders.ts` / `test/art.mjs` / `test/cache.mjs`
  **与 HEAD 逐字节相同** —— 改动没了；这 6 个文件（含 `render.ts`）的 mtime 全是同一秒。
- **根因**：同一工作区里有**另一路会话**在做全仓改动（当时 `ui.ts` 8276 行整文件变更、
  `profile.ts` / `camp.ts` / `forge.ts` 等同时在改，随后又新增了 `src/status.ts`），
  它的批量写入把未提交的内容一起覆盖了。`.gitattributes`（仓库一律 LF）也是那时候出现的，
  所以 `git diff` 会把整文件报成改动 —— 行尾噪声把真正的差异淹掉。
- **应对**（都已落地）：
  1. 改动先落一份 `git diff -w` 补丁做备份（`tools/tmp-r1.patch`，验完删）；
  2. 验证放在**隔离工作树**（`git worktree add --detach .tmp-head HEAD` + 只覆盖我改的 7 个文件）里做，
     于是"我的改动是否绿"与"对方当前是否红"互不干扰 —— 实测 10 套全绿；
  3. 把 `render.ts` / `types.d.ts` 按 `.gitattributes` 归一化成 LF（**只动行尾、内容 `git diff -w` 为空**），
     免得我的两行改动淹没在 1684 / 5149 行噪声里。
- **教训**：这个仓库的"多轮改动"必须假设**工作区可能被别人整文件重写** ——
  改动要小可重放、验证要能独立复现、文档要当场落盘。
