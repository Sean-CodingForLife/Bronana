# 18 · 地基体检

## 一、用户给的根因，与这次体检的形状

原话大意：**"你是 agent，总会丢上下文、注意力涣散，于是遗漏与偷懒；正确做法是用文档 +
完整无遗漏的自研体系去保证自动化、工程化、模块化、系统化的开发与运行。"**

⇒ 所以产出**不是一份散文**，而是三样结构：**① 算出来的地图**（生成物 + 门校验新鲜度）；
**② 缺口账本**（每条缺口要么指向判据，要么写明"刻意不做"）；**③ 把"清单完整性"本身变成门**。

## 二、交付

- `tools/foundation-map.mjs` + `docs/foundation-map.md`：六个类别**逐项清单 + 归属 + 谁守它**。
  数字全部现算（134 条命令 · 74 个工具 · 29 道门 · 67 套测试 · 145 个家族 · 98 个模块 · 39 份文档 · 34 步 CI）。
- `tools/_tables.mjs`：**登记表的唯一读法**（门 `registration` 与地图共用）。
  抽它的理由是自己刚犯过的那条：**同一张表被两处各解析一遍 = 迟早漂开**。
- 门 `doc-num` 新增两类判据：**基线哈希**（声明基线的行必须等于 `test/smoke.mjs` 的 `CASES`）·
  **生成物新鲜度**（盘上地图 == 现算）；白名单补上 `.github/pull_request_template.md`。

## 三、这一轮**算出来**的实害（不是假设）

| # | 发现 | 为什么严重 |
| --- | --- | --- |
| 1 | **`CONTRIBUTING.md`（家法正本）的指纹基线是上一代的值**（PR 模板同样） | 照它干活的 AI 会以为指纹该是那个数，于是去"更新基线"，把一次真实的行为漂移**合法化** —— 正是 `AGENTS.md` §五要防的事 |
| 2 | PR 模板写「现在 **49 套**」，实际 **67** | 同上：**模板说的判据 ≠ 实际执行的判据** |
| 3 | `docs/requirements.md` 写「跳过 49 套测试」、`CONTRIBUTING.md` 写「8 个系统」（实际 9） | 手抄的数字**没有任何门看得见**（白名单不含 `.github/**`，锚点不含这两类） |
| 4 | `tools/` **16 个工具没有任何引用**，其中 `tmp-readme-rows.mjs` **违反了"临时脚本验完即删"**、`rewrite-items.py` 是零依赖 Node 仓库里唯一的 Python | "靠人记住的规范"的活证据 |
| 5 | **14 条命令谁都跑不到** | "手工档"与"死命令"在机器眼里**无法区分** |

处置：**删副本、指向唯一出处**（家法正本与 PR 模板里的哈希块与套数都删掉，改成"跑命令看真值"），
再加上面那两条判据 —— 并**注入一行假哈希证明它会红**（`写的 deadbeef，实际 622d6ebf`）。

## 四、这一轮自己踩的三个坑（都当场修了）

1. **生成物自指**：地图里有一行"文档体系 N 份"，而地图**自己**就是一份 ⇒ `--write` 之后立刻 `--check` 失败（写一次涨一份）。
2. **生成物写日期**：加了时间戳 ⇒ 第二天必红。两条都写进了脚本注释。
3. **我又把判据写了两遍**：门 `registration` 第一版重写了 `test/persist.mjs` 的"加载器覆盖"，
   不认它的 `main`/`cli` 入口豁免 ⇒ **假红 7 条**；第二版又想文本解析**派生**的加载集（`RENDER = SIM + 1`）⇒ 再假红。
   ⇒ 于是有了 `tools/_tables.mjs`：**能 import 就 import，只能文本解析的必须过下限自检**。

## 五、外部对照（联网 + skill，三路）· 结论

- **引擎架构**：缺 loader（清单声明了 `plugins.enabled`、源码里没有加载器）· 缺"门 → 编译器"那一级 ·
  缺"抽象与宿主接触面"的声明（`null` 后端）。**明确不偷**：完整资源管线 · 跨平台逐位确定性 · ECS ·
  引擎级 UI 框架 · 音频中间件。**已做对、别人没有的**：扩展点两张表 + 一处自检 · 门自身的元门 ·
  两道指纹门 · 带真实 CTM 的绘制桩 · 美术宪法运行期拦截 · 引擎能力包 · SOLID 量化。
- **工具链 / CI**：**不建议**引入任何任务器 / 钩子框架 / ESLint 边界 / knip / 发布自动化 / SBOM 工具链
  （要么与已有门重合，要么在保护一个"没有发布产物"的不存在场景）。**最该做的一条不需要新工具**：
  **给 main 配 branch protection + 把 CI 设为 required status check** —— 现在任一门红**不阻止合并**。
  另两条低成本：CI 的 `uses:` 钉到 SHA · 给 workflow 加 actionlint（可搭在已有 `yaml` 门上）。
- **文档与 AI 协作**：**不缺"决策"这一层，缺身份（编号）/ 代价（consequences）/ 落点（哪道门守它）**；
  生成式对账可从"正则比对"升到"重写后比字节"（K8s 那一档）；`requirements.md` 370KB 建议先做**生成的目录**。
