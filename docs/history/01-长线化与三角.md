## 基础功能补齐（一轮审计 + 补齐记录）

起因是一句话："好多游戏该有的基础功能没有"。于是先**逐项验**了一遍，每条都记下证据，
再按"玩家会不会立刻碰到"排序补。下面左列是改造前的事实（都带位置），右列是现在的样子。

### 一、界面可达性

| 改造前 | 现在 |
| --- | --- |
| **设置只能从暂停面板进**（`index.html` 的标题页只有 开始/继续/操作说明）。想调音量必须先开一局 | `settings` 成为独立场景，标题页 / 暂停页 / 结算后都能进，返回时回到来处 |
| **战绩一直在写，没有任何界面读它**：`main.ts:64` 的 `gameOver → Save.addRun` 在累计，而 `Save.records()` 全仓只有 `test/persist.mjs` 在读 | 新增 `records` 场景（局数 / 最佳波次 / 最多击杀 / 最高等级 / 累计击杀与材料），结算页再加一行"历史最佳"对比 |
| **帮助浮层不能关**：`scene.ts` 里 howto 的 `keys:'none'`，`main.ts` 遇到 `none` 直接 return，只能点按钮 | 新增 `back` 按键组：帮助 / 设置 / 战绩 三者 Esc、回车、空格都能返回 |
| **破坏性操作没有二次确认**：`set-reset` 一下清空存档+记录+设置，`quit` 一下结束整局 | 同一个按钮点两次才生效（第一次换文案 + 3 秒倒计时，超时自动复位），不引入 `window.confirm` |

### 二、运行时

| 改造前 | 现在 |
| --- | --- |
| **失焦不暂停**：全仓只有 `input.ts` 清空按键，`visibilitychange` 零命中。桌面外壳里点开别的窗口，rAF 照跑、怪照打 | `blur` / `visibilitychange` → 自动暂停（走 `Scene.simulates` 判断，商店与选卡时不会插一脚），可用设置关掉 |
| **没有全屏切换**：`requestFullscreen` 零命中 | 设置里一个按钮，标签读的是 API 真实状态（F11 / Esc 改的也会跟着变）；浏览器与 Electron 同一个 API，不需要 IPC |
| **没有静音快捷键** | `M` 静音（放在场景分组之前，任何界面都能按） |

### 三、输入设备

| 改造前 | 现在 |
| --- | --- |
| **没有手柄支持**：`getGamepads` 零命中。手柄能移动能暂停，却**选不了升级卡** —— 因为升级卡只认 1-4 号键 | 手柄轮询：左摇杆 + 十字键移动，A 确认，B / Start 暂停与返回；菜单焦点让方向键 + 回车能操作**任何**界面（升级卡 / 商店卡 / 角色卡 / 所有按钮） |
| **移动端完全没法玩**：`index.html` 声明了移动端 viewport，但只有 `pointerdown` 用来恢复音频 | 浮动虚拟摇杆（按下处即圆心，拖动即方向，抬手即停）+ 一个只在 `pointer:coarse` 下显示的屏幕暂停键 |
| **键位写死**：`Input.moveVec()` 里硬编码 `a/d/w/s` | 五条可改键位（上下左右 + 暂停）写进设置表，点一下再按一个键即可改；重复绑定被拒绝，Esc 取消；**方向键永远额外有效**，改键不会把自己改到不能动 |

### 四、无障碍与视觉噪声

| 改造前 | 现在 |
| --- | --- |
| 抖动只能调小（`shake` 滑条） | `减少动效`：抖动直接归零 + 视觉粒子按计数器抽稀一半 |
| 伤害飘字不可关 | `伤害飘字` 开关（治疗 / 闪避 / 受击不受影响 —— 那些是低频且重要的反馈） |

**减少动效不许消耗模拟随机数**：抽稀按计数器（隔一个丢一个），不按 `S.rnd()`。
用随机数抽稀等于让"画面设置"改变模拟的随机序列，同一份录制换个设置回放就分叉。

### 顺手挖出来的三个真 bug

补功能的过程里撞见三个**原本就在**的缺陷，都不是新代码引入的：

1. **`_pauseFrom` 会被覆盖**（`game.ts`）：`setState` 每次进入 `paused` 都重写来处。
   于是"暂停 → 设置 → 返回 → 继续"会**又回到设置**（实测复现：探针打完三步后状态停在 `settings`）。
   这条在只有"帮助"一个覆盖层时就能触发，只是很难碰上。
   修法：暂停的来处只记**真实对局状态**（playing/levelup/shop）。
2. **覆盖层互跳会来回弹**：如果允许 `设置 ⇄ 战绩`，进入 B 会改写 A 的来处，
   于是 A⇄B 无限往返、永远回不到真正那一屏。修法：三个覆盖层之间**互不相通**，
   只能从真实屏幕进 —— 出边表里没有的来处，`Game.returnFrom()` 会退回 title。
3. **模块级状态盘点对带类型注解的 `var` 隐形**（`test/persist.mjs` 的静态判定）：
   它用"声明行前是不是 `var`"来判断名字，于是 `var x: T = ...` 整个名字匹配不上标识符正则。
   我新加的 `_capture` / `_padKeys` / `_stickEl` 就是这么漏过去的 —— **测试自己的漏洞**，
   已修（现在多认出 6 个状态，之前 34 → 40）。

### 这一轮**没有**做的（它们不是"基础功能"，是内容）

难度 / 危险等级、武器道具图鉴、角色解锁的元进度、i18n、色觉友好调色板。
另外有一个诚实的覆盖边界：**"设置 → 行为"的接线在 `main.ts` 的 `applySetting` 里**，
而 `main.ts` 是入口模块、按设计不被任何模块 import（见 `test/ui-check.mjs` 的分层检查），
所以这一步只能在浏览器里验证 —— 测试侧守的是"设置项被写对了"，
以及 `test/registry.mjs` 的静态契约"每个设置项都有应用分支"。

## 长线化 —— 模拟经营与角色养成（**P0 · P1 · P2 · P3 · P4 已完成**）

> **先说清楚它是什么：一个**离线单机游戏**。** 没有服务器、没有账号、没有榜单服务、没有推送，
> 也不会催你回来。这一节说的"长线"指的是**内容够多、可以反复玩**，不是"运营"。
> 下面出现的"赛季""每日/每周""成绩码"都按单机的方式实现：
> 种子由日期/周次算出来（谁算都一样，不需要服务器），成绩靠玩家之间**交换字符串各自本地复算**。
> 只要看到像是在描述一款联网运营游戏的句子，那就是写过头了 —— 请按这条纠正。
>
> **状态：** P0（账号档案 + 挑战→解锁 + 三态图鉴 + 面板 + 角色门槛）、
> P1（难度阶梯 + 通关条件 + 每日挑战共享种子 + 成绩码）、
> P2（角色天赋树，只改开局条件）、
> P3（两级模拟经营：局内营地 + 跨局据点，两条循环互供）、
> **P4（离线产出 + 每周挑战）** 都已做完并验证 —— 四步全部做完。
> 这一节同时写清"别人怎么做""本作的处境允许怎么做""顺序为什么是这个顺序"，
> 免得一上手就在错误的地基上加层。

### 二、从这四份一手材料里提炼出的六条原则

1. **阶梯要"数值 + 结构"混合，后期靠换招而不是加数字**（StS 的 17/18/19 级）。
   加数字的边际体验趋近于零，换招式才是内容乘数。
2. **阶梯按角色独立推进**（StS）。这一步的价值不只是难度 —— 它天然就是"角色养成"的载体：
   每个角色有自己的进度条，就有理由反复使用同一个角色。
3. **每级仍然全部可选**（StS）。不做"解锁了就必须变强"，玩家想轻松打就轻松打。
4. **天赋树要有分级与取舍**（PoE）：小点 / 显著点 / **同类互斥的精通** / **改变运作方式的基石**。
   纯粹"每级 +2% 伤害"的树不构成选择；**互斥**才构成选择。
5. **养成要有代价与风险**（Monster Rancher）：疲劳、忠诚、训练风格三件套说明"变强"可以是
   一个有张力的过程而不是一条加法曲线；但**代价要可恢复**（它让怪物死亡，本作不建议照抄）。
6. **经营的可玩性来自布局与瓶颈**（Two Point Hospital / RimWorld），不来自数值增长。

### 三、本作的处境：三条事实决定路线

1. **持久层只有三把键**：`bronana.settings` / `bronana.run` / `bronana.records`（`storage.ts`）。
   **没有"账号级"存档** —— 任何跨局长线机制都缺地基。这一层必须先有。
2. **资源只有一种**：材料 = 经验 = 货币，同一个字段。经营与养成天然要多资源，
   而"多货币"是有名的设计债（[multiple currency types](https://github.com/raduacg/game-mechanics-optimizations/blob/main/I_46_multiple_currency_types.md)）——
   得**先决定加几种、为什么加**，而不是边做边加。
3. **模拟层是确定性的、可回放**（`record.ts` 的带子 + `tools/fingerprint.mjs` 的行为指纹）。
   由此得到一条硬约束：**养成与经营只能改"开局条件"，绝不能进模拟层**。
   改局内数值曲线会当场打穿回放与指纹 —— 这条约束同时是护栏，越界会被测试抓住。

### 四、四条轴：**做深**的版本

已定：局外永久强化**要做深**（多级天赋树），模拟经营**两级都要**。所以下面写的是目标形态，不是最小版。

**A · 局外成长（元进度）** —— 所有长线机制的地基
- `bronana.profile` 持久层：独立 `VERSION`，复用 `save.ts` 已有的 `MIGRATIONS` 机制。
- **挑战声明表**（Brotato 那张表的形状）：四组 —— 阶梯类、累计击杀类、累计资源类、属性/行为阈值类。
  每一行声明"条件 → 解锁什么（角色 / 武器 / 道具 / 天赋点）"，登记进 `registry.ts` 与现有 27 个家族同源审计。
- **图鉴**：武器 23 / 道具 29 / 怪物 10，每条三态（**见过 / 用过 / 满级过**）—— 三态比"见过"多一层驱动力，
  且实现上只是 profile 里的一个位图。
- **局外货币**：由局内表现的**一个子集**折算（不是材料全额），在局外买天赋点与设施。
  加货币的同时必须回答"它为什么不能是材料"。

**B · 角色养成 —— 多级永久天赋树**（用户已选"做深"）
- **每角色一棵树，骨架共享、起点不同**（PoE 的做法）。本作 8 个角色已经是"数值 + 一个特殊机制"，
  天然适合：起点落在各自扇区（近战/远程/工程/元素），交界处是混血点。
- **四级节点**（PoE 的分法）：
  - 微点：单条小属性（+1 移速、+2 生命）
  - 显著点：强化该角色的**特殊机制**（例如受虐狂的怒气转化率）
  - **精通**：同一类簇里选一个，且**同类精通全树只能选一次**（互斥 = 选择）
  - **基石**：改变角色运作方式，**收益与代价并存**（"攻速 +40%，但无法暴击"这种）
- **阶梯与树共用一条曲线**：StS 的"每角色独立 Ascension"正好可以当树的经验来源 ——
  打高阶梯给更多天赋点，于是"挑战更高难度"和"养成"是同一件事的两个面。
- **洗点**：有成本但不可痛（PoE 的社区结论）。建议给每角色固定次数的免费洗点 + 之后消耗局外货币。
- **硬约束**：树的产出**只能进开局条件** —— 起始属性、起始武器、起始词条、起始资源、开局一次重掷。
  **不得**修改局内成长曲线（`Stats` 的收益递减、波次强度曲线都属模拟层）。

**C · 模拟经营 —— 两级都要，且必须互供**
- **局内营地**（波次之间的新场景，与现有商店同层）：
  建/升级设施 → 给**本局**的每波被动（开局一次重掷、每波首杀回血、商店多一个槽位）。
  结算清零。参照 Monster Rancher 的**工作 / 训练 / 休息**三角：营地里的投入要**占用本局资源**，
  所以"这波投营地还是投自己"是一个真实取舍，而不是免费加法。
- **跨局据点**：永久设施树，解锁**功能**而非纯数值 —— 更多商店槽位、更多重掷次数、
  开局可选起始武器、更多角色槽、天赋树的上限。功能解锁不会稀释"每局从零开始"。
- **两条循环必须互供**（Cult of the Lamb 的核心教训）：
  远征产出 → 据点变强 → 远征能走更远 → 产出更多。任一环节断开就退化成两个半成品。
- **瓶颈才是玩法**（Two Point Hospital / RimWorld）：营地的乐趣来自"设施位置/产能/人力怎么排"，
  所以要有一个**可见的瓶颈**（空间位、人力、每波只能收一次产出），而不是"有钱就点满"。

**D · 复玩理由（不是"运营"）**
- **难度阶梯**（StS 式，1-20 太长，本作建议 8-10 级）：前 2/3 级是数值，后 1/3 级**换怪与换招**
  （新敌人行为、Boss 复数出场、波次结构变化）。每级解锁一个角色或一件武器。
- **每日挑战（共享种子）**：同一天全世界同一个种子，比波次/击杀/用时。
  本作已有确定性 + 种子 + `record.ts`，这一步技术上几乎免费。
- **成绩码**（见第五节）：**可离线互验**的成绩字符串 —— 玩家自己对，没有榜单服务。
- **每周挑战**：可选档，且**可跳过**（不强制重开）。它替代不了 PoE 那种真赛季
  （那需要服务端与一条内容生产线），能诚实做到的就是"每周一套不同的固定条件"。

### 五、一件本作独有的便宜事：**成绩可复算**

因为模拟是确定性的、`record.ts` 能按带子逐帧重放，所以**成绩不需要信任提交者**：
给出 `seed + 输入序列`，任何人（哪怕是一个静态页面）重放一遍就能验证真伪。

于是**不需要榜单服务**：玩家之间交换一句"成绩码"，各自在本地复算。
这条也顺带约束了挑战的设计 —— 条件必须人人相同（所以挑战刻意不接天赋与据点）。

这是确定性架构第一次直接变成产品能力：前面几轮它是"可测性"与"可复现 bug"的成本，
到这里开始产生功能价值。

**顺手抓到的两个真问题**

1. **"更难"反而把 Boss 取消了**：`bossEvery` 一开始写成**替换**基准间隔。
   改成 4 之后，第 5/10/15/20 波里凡是不满足 `wave % 4 === 0` 的那几波**就没有 Boss 了**
   （第 10 波 `10 % 4 = 2`）—— 难度提高、Boss 反而变少。
   修法：与基准的每 5 波取**并集**，只加不减。测试里专门有一条"提高难度不会取消任何原有的 Boss 波"。
2. **`enemySpeed` 是死配置**：声明在表里、写进了基准，但**没有任何一级用它**。
   测试的"每个键都至少被某一级用到"当场抓出来，于是把它挂到第 7 级（"凶性"），
   顺带让那一级不只是加伤害。

**一条诚实的设计边界**：`poolShift`（怪物池按 wave+N 取）只在**前几波**有咬合力 ——
非 Boss 怪在第 7 波就全解锁了，所以 7 波之后这条修正不再改变任何东西。
这一点写在了 `danger.ts` 的 NOTES 里，也正因为它不够，第 8 级才补上 `bossEvery`（全局有效）。
**"某条修正在大部分情况下不生效"是最难发现的一类问题**，所以它被写进注释而不是留给读者猜。

**为什么每日挑战用 UTC 而不是本地时区**：本地时区会让"今天"在两个人那里指不同的一天 ——
同一天的两个人打的不是同一局。

测试怎么验这一条（**这里踩过一个坑，值得记下来**）：一开始的写法是
"改 `process.env.TZ` 到 UTC+14，再算一次，断言日期键相等"。那条判据在 **glibc 上恒真** ——
Node 一旦用过 `Date`，时区就被缓存了，Linux 常常不再重读环境变量。所以它看着在守
"时区无关"，其实什么都没验，而它在本机（Windows/ICU）与 CI 上**都会过**。
现在两条一起做，各自补上对方的盲区：

1. **真的在新时区的子进程里算**：`TZ` 在**进程启动前**就设好（UTC / UTC+14 / UTC-10 各跑一遍），
   绕开"时区被缓存"这件事；
2. **静态判据**：源码里不许出现本地时间分量的读取（`getHours` / `getDate` …
   —— `getTime()` 不算，它返回 epoch 毫秒，与时区无关），这条与平台无关。

只做 2 会被"用了 `getUTC*` 但拼错字段"骗过；只做 1 会让这套测试依赖平台能否重读时区。

**每日挑战无视角色解锁门槛**：所有人必须用同一个角色才可比；顺带它也是一次"试吃"——
没解锁的角色今天能用。

**"可复算"不是一句话，是一条端到端断言**：`test/daily.mjs` 里真的录 600 帧 → 出成绩码 →
重放 → 波次/击杀/等级逐项对上；然后三种作弊各自验不过：

| 作弊 | 拦住它的检查 |
| --- | --- |
| 改成绩码里的数字（哈希仍匹配带子） | 重放结果与成绩码不符 |
| 改带子（改一帧输入） | 哈希对不上 |
| 保留哈希但虚报成绩 | 重放结果不符 |

**顺手抓到的三个真问题**

1. **分享出去的带子会验不过自己**（最严重的一个）：哈希的规范序列化里
   `String(undefined)` 得到 `'undefined'`，而**分享串是 JSON**
   —— `JSON.stringify` 会把数组里的 `undefined` 变成 `null`，于是"打包再解回来"哈希凭空变掉。
   修法：规范序列化时把 `undefined` 与 `null` 归一成同一个（都表示"缺省"）。
   这条是测试当场抓到的（"同样内容的带子 → 同一个哈希"那条），不是推出来的。
2. **回放会往存档里写假数据**（既有 bug，被这次改动暴露）：回放会真的推进模拟并跑到
   `gameOver`，而 `gameOver` 的接线会写战绩与账号档案 —— 也就是说**按 L 放一遍录像，
   就凭空多了一局战绩**。修法：`Rec.replaying()` + 接线层四个落账点全部先问它
   （测试断言这四个点都在问）。
3. **回放 `newRun` 时把难度参数丢了**（既有 bug）：`Rec.play` 重新拼参数时只补了种子，
   `args[2]`（难度）被丢掉 —— 于是高难度的带子会回放成第 0 级，
   而"逐位一致"会变成一个**看起来成立、其实验的是另一局**的假象。

**证据**

- `test/daily.mjs`（新增第 23 套，60+ 条断言）：UTC 边界与时区无关、共享种子、角色轮换、
  成绩分公式、成绩码格式的拒绝路径（坏日期/坏角色/坏哈希/坏版本前缀）、
  哈希的敏感性（改输入/种子/难度参数都变）、**JSON 往返哈希不变**、
  端到端重放验证与三种作弊、回放期间不落账、每日记录的取优与坏档修复、总账与接线。

#### P4 实测记录（离线产出 + 每周挑战）

**先说清楚"赛季"这一档为什么不做**

PoE 那种赛季 = 新机制 + 全新经济 + 一条内容生产线，那是**联网运营**的做法，
对一个离线单机游戏来说既做不到、也不该硬做（做出来只会是换个名字的每周挑战）。
这里能诚实做到的是**每周一套固定的共享条件**：种子由周次算出来，谁算都一样，
不需要服务器，也不需要你按时回来 —— 什么时候想打都行，那一周的局永远在那儿。
这条边界写进 `season.ts` 的文件头注释里，免得后来者以为它是没做完。

**做了什么**

| 新增 / 改动 | 说明 |
| --- | --- |
| `offline.ts`（新增，93 行） | 速率表 + 纯函数 `settle(elapsedMs, sporebedLevel)`。等级 1 → 0.10 孢子/分，等级 2 → 0.18；**低于 10 分钟不结算**；**单次封顶 8 小时**。满级满额 = **86 孢子**（一局通关约 93）—— 挂机是补充，不是替代 |
| `season.ts`（新增，122 行） | UTC 的 **ISO 周**键 `YYYY-Www` + 当周种子 / 角色 / **难度轮换**。难度从第 1 级起轮换（不轮换第 0 级：每周挑战总该比每日紧一点） |
| 离线产出的**开关**是据点设施 | 没买菌床 → 速率为 0 → 一点不给。它不是一个新界面、不是一个默认开启的系统，而是一个已经存在的长线系统的回报 —— 这样"要不要离线产出"对玩家与对设计都是一次显式选择 |
| **结算即前进**（放置类最经典的漏洞） | `Profile.settleOffline()` 无论给没给，都立刻把 `lastSeen` 推到现在。于是反复刷新页面、反复开关标签页都拿不到东西 —— 每次都得有真实的间隔。**没买菌床时也前进**，否则"先挂 3 天再买菌床"会一次性补发 |
| 未来的时间戳一律丢弃 | 坏档里的 `lastSeen` 若在将来，读档时直接当"第一次见面"（`profile.ts:124`）。改系统时间往前跳不会白拿 |
| 每周挑战**不接养成** | 与每日同一条纪律 —— 挑战要全体同条件。为了不把这条纪律抄两遍，每日与每周**合并成一个入口** `startChallenge(kind)`，规则推导留给 `daily.ts` / `season.ts` |
| "这一局是不是挑战局"的标记挪到接线层 | 原来放在 `daily.ts`（`begin/current/isDaily/frames/end`）。它属于接线层：模拟层与规则模块都不该知道"玩家正在打挑战"。现在就是 `main.ts` 里一个 `challenge` 变量，且**显式登记**进 `persist.mjs` 的模块级可变状态清单 |
| 图鉴面板加两行 | "本周角色 / 难度"与"离线产出"（没买菌床时明说"它是开关"）—— 长线机制必须能在界面上看到状态，否则玩家不知道它在运转 |

**诚实披露：本地时钟可被改**

离线产出读的是 `Date.now()`，而本机时钟归玩家管 —— 所以"离线了多久"这件事**在单机里不可信**。
这里的选择是承认它，而不是假装防住了：

- 额度刻意压得很小（满级 8 小时 ≈ 一局通关），改时钟的人只是在缩短自己的游戏；
- 它**不进成绩码**、不进任何排行榜字段 —— 成绩码只认 `seed + 输入序列`，重放验证根本不读时间。
  所以"改时钟"骗不到任何有可比性的东西。

**抓到的两个问题（都是我这轮自己写的）**

1. **新增的模块级可变状态没登记**：`main.ts` 里的 `challenge` 标记一加，
   `persist.mjs` 的盘点当场报 `main.ts:challenge`。
   这就是那套测试存在的意义 —— 跨局状态必须显式登记，否则"哪个变量在偷偷跨局活着"没人查得出来。
2. **静态断言被重构打断**：`keep.mjs` 里那条"每日开局只传（角色, 种子, 难度）"写死了
   `function startDaily`。把每日/每周合并成一个入口之后，正则匹配不到 → `body` 变成空字符串 → 断言直接 FAIL。
   这次算走运：它恰好是"**必须包含**某个字符串"的写法，空字符串必然失败。
   **反例才可怕** —— 紧跟它后面那条是"**不许包含** `openingOf` / `keepOwned`"：
   拿空字符串去断言它，会**永远通过**，纪律断了也看不出来。
   修法是两者都改成断言共用的 `challengeRule` / `startChallenge` 里的具体内容，
   顺带把"每日与每周共用一套流程"也钉住。
   **教训**：静态断言要偏向"必须包含某个具体字符串"，而不是"不许包含"。

**证据**

- `test/extras.mjs`（新增第 27 套，60+ 条断言）：速率表的完整性与单调性、门槛与封顶、
  **结算即前进**（同一时刻再结算一点不给 / 没买菌床也前进 / 升级后同样间隔拿更多）、
  坏档不刷（未来的时间戳）、ISO 周（同周同键 / 跨周换键 / **跨年 2027-01-01 → 2026-W53** /
  改时区不影响 / 补零让字符串序 = 时间序）、难度与角色确实在轮换、每周记录只留更好的那一局、
  **挑战不接养成的两侧对照**（挑战入口不许有 `openingOf`/`keepOwned`；
  **普通入口必须有** —— 否则天赋与据点就是白买的）、同样参数跑两遍逐帧一致、界面与入口。
- `tsc`（web + node）0 错；**27/27 套测试通过**；`registry` 家族 44 → **46**；状态仍 **14**；
  `vite build` 46 模块 / 256.54 kB（gzip 94.14 kB）。
- **行为指纹与基线仍逐位一致**（`5f763627` / `a00dad64` / `b1d751da`，4800 帧）——
  P4 整个是"开局之前的输入"与"局外的账"，跑局流程一位没动。

## 把三角做深 + 地牢化（**A–F 已完成**；G1/G2 见下面两节）

上一节把四条轴铺开了，这一节是把它们**做实**：每条边都补上、每个系统都自测过。
顺序是 A → D → B → C+E → F，中间还做了一次**全项目模块化体检**。

### 一、四条边补齐

| 批次 | 补的是哪条边 / 哪个缺口 | 做了什么 | 实测 |
| --- | --- | --- | --- |
| **A** | 养成 → 经营（原来最细的一条） | 天赋树加第 5 个扇区「经营」6 节点：折扣 / 收获 / 幸运 / **每波材料** / 孢子产出；新增 `econ` 效果形态 → `S.omods`（与 `dmods`/`kmods` 同形同读点） | 12 种子 clear 模式：**战斗流波次最高（+1.8）、整套经济材料最高（+276）、贪婪流孢子最高（×3）**，三个指标各有最强者、**无人支配** |
| **D** | 经营自己的玩法（原来只有"3 个位子"） | 营地设施按**建造顺序**排成一行，**相邻**命中组合表才生效（5 个组合成环）；卖掉落单会同时断两个组合 | 同一批设施换个顺序差 **0.6~2.4 波**；一行 3 个位子最多挂 2 个组合 |

| **C+E** | 据点是全项目最浅的一层 | 设施 6 → **10**，加**前置链**（仓库→菌床/货栈、工匠→工坊、钟楼→档案馆、货架→靶场）与三个**结构性解锁**：工坊（刷新保底 T3+）/ 靶场（开局多带道具）/ 货栈（商店必出在用的武器类别） | 买满 955 → **1995 孢子**（≈28 局）；自检新增"无环 / 前置等级不超上限 / 不许自己要求自己" |
| **F** | 战斗 × 养成缺"组合"这一层 | 新增 `synergy.ts`：**武器家族**（把 22 个造型关键字归成 5 个玩法家族）+ 三条轴（同家族 / 同系 / 同元素），件数达到档位就给增量，**只取最高档不叠档**；G5 补上同一份表里的**道具套装**（4 套，29 件道具全部有归属） | 家族容量 4/4/5/4/7；3 把同家族 = 攻速 +10%；**1 把武器 = 恒等**（指纹前提）；道具套装实测见 G5 那一节 |

**A 的关键结论**：本作的材料几乎全来自击杀，所以"更能打"本身就是最好的经济 ——
经济流在波次上**赢不了**。于是把它做成 **meta-forward**：少打一两波，多拿两三倍孢子
（这就是 Dead Cells 的 Gold Reserves / Recycling 的形状）。另一条是参照 Brotato 的
**每波结算材料**（与击杀脱钩），否则纯经济流没有立足点。

**F 的关键结论**：直接照抄 Brotato 的"同名武器 N 把"在本作**是死的** ——
22 种造型关键字里只有手枪有 2 把，阈值 ≥2 的轴永远触发不了。
所以先补一层**声明**：家族是玩法分组，kind 只是造型关键字。这也让"以后往某个家族加武器"
自动变成"这条轴更强"。

### 二、一个测量 bug 与它的教训（值得单独记）

做营地实验时，数据说**连"每波回血 +3"的营火都让成绩变差 −1.3 波**。纯增益不可能有害 ——
查下去是我的**实验台**坏了：预建营地时把状态留在 `shop`，机器人多吃了一次商店回合，
而回合末尾是 `nextWave()`，**第 1 波整波被跳掉**。

> **教训：遇到违反常识的数据，先怀疑测量，不要调平衡。**
> 我差点顺着那批假数据继续改价格（甚至已经据此论证过"营地亏 → 要给独立货币"）。
> 修正后的真实结论是：单体设施 ±0.3 波（近中性）、组合 +0.5~+0.8 波、
> 同一批设施换个顺序差 0.6 波。实验台现在会**断言预建营地不推进波次**，坏了直接抛。

### 三、模块化体检：把"散落"收口，并留下守卫

架构体检（`tools/arch-audit.cjs`）先说结论：**依赖图无环、没有真死接口**。
但有两类"散落"是真问题，都修了：

1. **效果文案被抄了六份**。据点/营地的一个效果键"叫什么、怎么写给人看"散在
   `ui.ts` 的当前效果行与"下一级"、`ui.ts` 的营地两处、`camp.describeState`、
   `stronghold.describe` —— 加一个键要改六处，漏一处就是"效果生效了、界面上看不见"。
   现在**键自己带 `note`（给开发者）与 `text(v)`（给玩家）**，界面只做翻译；
   并加了守卫：*每个声明的键都必须能产出人话*、***`ui.ts` 里不许再出现效果键字面量***。
2. **模拟层里藏着一个硬编码的 3**（工坊"保底 T3"）。现在"保底几级 / 多带几件 / 必出几件"
   都写在据点表的**值**里，模拟层只读不写死。

顺手还做了：`story.ts` 里一个声明了没人用的字段删掉；地牢地图层加了**"待接线"守卫**
（`src/` 里除自己外没人 `import dungeon.ts`、没人调 `Dungeon.*` ——
G2 接上之后这条会变红，提醒更新账本）；测试里写死的数量改成**从表里取**
（加一把武器不该让一条无关测试红，那种红会养成"顺手改数字"的习惯）。

**已知的技术债（诚实列出，未处理）**：`game.ts` 1951 行（扇出 19）、`ui.ts` 1602 行
（88 处类型字符串分支）、`Session` 有 **54 个字段**。这三个是"大文件/上帝状态"，
拆它们要动模拟层核心，属于独立的架构任务，不在本轮范围内。

### 四、地牢地图层（`dungeon.ts`，G1 已完成）
`(种子, 层号) → 一张地图`，纯函数、零可变状态。算法是**以撒那一套的简化版，但规则照抄**：
随机生长 → **死路留给特殊房** → **Boss 房放最深死路** → 宝箱/商店/营地各一间 →
**密室 = 与 ≥2 个房间相邻的空格**，它到每个邻居的门都是**暗门**。

跑 **300 个种子 × 3 层 = 900 层**验证性质（不是"生成出来看着对"，是**性质**）：

- 不破墙能走到每一间普通房；**密室不破墙绝对进不去**（隐藏才是隐藏）
- 每层恰好一间 Boss 房，且在**最深的死路**、离入口 ≥2 步
- 密室都有线索种子、初始"未发现"、可以从 ≥2 面墙破进去
- 同种子必得同图（**于是"共享种子"直接等价于"同一天全世界同一座地牢"**）

**跑 900 层抓到的三个真 bug**：① 有些种子生出一层没有死路的图（3×3 方块就是反例）→
**那层根本没有 Boss**；② 第一版补救"从最深的房间一路往外接"→ **把 7×7 网格填满、
还是零死路**（每接一间就吃掉一个死路，净收益 0）；③ **密室挨着 Boss 房之后，
Boss 房就不再是"死路"** —— 是我的断言写错了（应该是"非暗门的邻居恰好一个"）。

### 五、剧情层（`story.ts`，骨架 + 第一批内容）

**没有另起一套设定，而是用游戏里已经长出来的名词当骨架**：
你是从**菌床**里长出来的一根东西，荒漠正被**菌毯**吃掉，四个 Boss 是它的四个器官，
上一个文明留下 **12 片记录**，真结局在通关之后的**深井**。

四位枢纽 NPC 各对应一个**已有设施**（菌母=菌床 / 拾荒者=拾荒堆 / 守钟人=钟楼 / 记录官=图鉴），
借的是 Hades 的"死亡也推进剧情"、以撒的"结局是收藏"、挺进地牢的"角色过去"、
死亡细胞的"碎片拼世界观"、杀戮尖塔的"事件=选择"。

**隐藏要素 × 剧情**：真结局「回信」= 通关 + 12 片 + 下过深井（flag 卫兵），
而 12 片里有 **4 片只在密室** —— 想读完这封信，必须去破墙。

测试守的是**性质不是文案**：开局不许剧透（深层设定一个词都不许出现）、条件随进度解锁
（死亡 → 层数 → Boss → 碎片，30 条全部可达）、碎片来源闭环（正好集齐 12 片且不重复）、
真结局有 flag 卫兵、**剧情不碰模拟层**（对话不进带子）。
其中一条是结构性的：**flag 是字符串，写错一个字母那句台词就永远取不到而界面毫无异常** ——
所以加了 flag 声明表 + 双向校验（用了的必须声明、声明了的必须被用）。

## G2：把地图接进对局（**已完成**，G1 的地图层从此接上了对局）

地图层原来只是"长出来了"，这一轮它变成了真正的战斗：**一间房 = 一波遭遇**，
门是选路，墙是秘密，三层是长度。

### 一、接缝在哪，为什么这么接

| 接的东西 | 怎么接的 | 为什么 |
| --- | --- | --- |
| **房型/层主题 → 刷怪** | `Dungeon.modsFor` 产出**与 `danger.ts` 同名同折法**的键（`waveBudget` / `eliteChance` / `poolShift` / `enemyHp` / `enemyDmg` / `bossEvery`），`Dungeon.foldMods` 把难度那一份与它折成**一份**，`startWave` 里算一次存进 `S.wmods`；`buildWave` 与 `spawnEnemy` 一行都没改 | 键名 = 读取名是这一层的命根子。地牢若自创 `hpMul2`，`buildWave` 读不到它，而"声明了却没人读"只能靠人眼查。测试做**跨模块对照**：地牢的每个键都必须能在 `danger.BASE` 里找到同折法的 |
| **房间内容** | `game.ts` 的 `ROOM_FX` 表：每种房型一行（进门效果 + 商店货架/折扣），事件房另有 4 条遭遇表 | 房型没有内容 = 走进去什么都不发生，那正是"浅尝辄止"的样子。测试断言**每种房型都有内容**、每条遭遇都真的改了状态、且都写明代价 |
| **门** | `enterRoom(dir)` 是唯一入口：门存在 → 这一间清干净 → 暗门要先打穿；`updatePlayer` 里"走到门口就过去"也调同一个内部函数 | 三道校验各对应一个设计决定。"边打边跑"必须不成立，否则可以永远躲怪 |
| **清除即过** | `step` 尾部：刷完 + 场上清空 → `endWave`；时限到期 → 剩下的怪**狂暴** + 停止补怪 | 计时器从"要撑多久"变成"多久内打完"。时限内清完 = 材料 **×1.2**，超时 = **×0.8**（实测 46 vs 30） |
| **自动探索** | `nextWave`（商店/营地里的"下一波"）→ `autoExplore`：最近的一间**没打过的**可达房（暗门不算通），优先特殊房 | 无头测试与不想导航的玩家都要一条确定性的默认路径；**密室永远不会被自动走进去**（隐藏要素得玩家自己发现） |
| **存档** | 只存进度：层号 / 当前房 / 清过的房 / 发现过的房 / 破过的墙 / 发现计数；地图由种子重建 | 存档小、且"同种子 = 同地牢"这条性质连读档都保持 |
| **界面** | 小地图（DOM，7×7，只画**发现过**的房间）+ HUD 加"所在"一栏 + 门与暗门墙画在战场上 | 隐藏房在破墙前**根本不在 DOM 里**：界面不可能剧透，也不可能被误点 |

### 二、这一轮改出来的五个真 bug（都是被测试或实测抓的）

1. **宝箱房刷出了 Boss**。Boss 规则是"每 5 波一只"，与房型无关 —— 于是第 5 波的
   宝箱/商店/营地房（预算为 0）里也塞进一只。修法：`m.waveBudget > 0` 才允许出 Boss。
2. **超时之后这一间永远结束不了**。超时会 `forceClear`（停止补怪），但 `spawnIdx`
   再也追不平队列长度，于是"刷完"永远不成立、门永远不开。修法：`drained` 要把
   `forceClear` 算进去。
3. **超时奖励那一档从来没生效**。`endWave` 开头就把 `forceClear` 复位了，然后才去读它
   决定 ×1.2 还是 ×0.8 —— 两档永远相等。测试量出来是 46 vs 46 才发现的。
4. **事件房是"表里有、局里没有"**。房型表声明了 `event`，生成器从来没放过它。
   测试断言"四种特殊房各恰好一间"当场变红；修完顺便把死路下限从 4 提到 5。
5. **难度 6 的方向被改造反转了**。`waveTime` 从"要撑多久"变成"多久内打完"之后，
   ×1.08（更长）从惩罚变成了福利。现在改成 ×0.92，并在 `danger.ts` 里加了
   `DIRECTION` 表显式声明"这个键越小越难" —— 测试的"难度只增不减"按方向判，
   而不是把这条签名反转当成违规。

### 三、节奏：一个必须先量、不能拍脑袋的数字

房间制把"一步"从一波变成了**一间房**（十几秒），而一局从 20 波变成了 3 层 × 十几间 ≈ 40 步。
成长曲线一个字没改，步数却翻倍 —— 同一个机器人**从第 12 波掉到第 4~5 间**。
所以加了一个旋钮 `Enemies.PACE`：`equivWave(w) = 1 + (w-1) × PACE`，
"第 N 间房等效于旧设计的第几波"。`PACE = 0.55` 时第 39 间 ≈ 旧第 22 波（原来一局通关的水平）。

`tools/balance.mjs pacing` 的实测（12 种子）：

| PACE | 第 39 间等效旧波次 | survive 中位间数 | clear 中位间数 | 平均材料 | 平均孢子 |
| --- | --- | --- | --- | --- | --- |
| 1.00 | 39.0 | 4 | — | 87 | 12 |
| 0.70 | 27.6 | 5 | 9 | 548 | 40 |
| **0.55** | **21.9** | **6** | **9** | **538** | **41** |

读法（诚实的部分）：`survive` 模式的机器人是**故意平庸**的那个（改造前它也只活到 4~5 波），
它的绝对数字不能当玩家水平用；它能说明的是**相对**关系（0.55 比 1.0 多活 1.7 间、多拿 78 材料）。
`clear` 模式（免伤）12 个种子全部一路推进、**没有任何一次卡住/走不动**，
中位 9 间 / P90 12 间，说明地图与门这套流程是通的 —— 它停在 24000 帧上限，
不是撞墙。G3（随机 Boss 池）落地后两组数字都复测过，都在噪声内没动
（survive 6.2 间 / 155 材料 / P90 9；clear 9.6 间 / 537 材料 / P90 12）——
Boss 池只影响 Boss 房，而这个机器人在帧上限内一次都没走到 Boss 房。
**"好不好玩"仍然测不出来**（这一条从上一轮就写在 README「已知取舍」里，没有变）。

据点那一套在同一套实验里复测，结论没变（12 种子 survive，增量相对"无据点"）：
仓库满级 波次 +0.7 / 材料 +54；**地基+工匠 ±0**（营地策略是 never，隔离有效）；
结构性三件套（货架+工坊+靶场+货栈）**波次 +1.8 / 商店件 +6.8**；全部满级 +2.1 / 孢子 +22。

### 四、行为指纹：这一次是**故意**变的

`5f763627 / a00dad64 / b1d751da` → `4a89e77d / 62b9f577 / 21b2e870`。三条原因：

1. 一波的刷怪量现在由**房型 × 层主题**决定，而且指纹的起点从"第 1 波"改成"一间普通战斗房"
   （入口间不刷怪，测它会得到一片空场 —— 那等于把这一段测废了）；
2. 敌人成长按 `equivWave` 摊开（`PACE = 0.55`）；
3. "清空即过"取代"撑满计时器"，随机数消费点随之变化。

这组基线**不是被随手改掉的**：先跑一次看它确实变了、再逐条对上是哪一处变更造成的。
（历史上另有一次：容器统一回收时 `a00dad64` 取代 `ac2a349e`，也是有意接受。）
