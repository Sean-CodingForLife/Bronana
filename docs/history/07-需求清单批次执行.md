## 一、批次一 · 开局流程（`c0da764`）

### 做了什么

用户 2026-10-01 的原话是流程三步 + 十条系统。这一批做**流程那一半 + 时装那一条**：

| 新增 | 是什么 | 坐哪一层（以及为什么） |
| --- | --- | --- |
| `src/character.ts` | **存档角色**："这个档里的那个人"（名字 / 外观 / 初始职业 / 入门三选） | L0。改造前**没有这个概念** —— 选人是每局一次的动作、不进存档 |
| `src/appearance.ts` | **外观系统**（用户点名的第 9 条"时装"）：8 色板 × 3 脸型 × 5 配件，全程序化 | L0。零素材是 B02 / R30 的硬约束，所以"时装"只能是配色与配件的变体 |
| `src/openings.ts` | **入门三选**：初始技能 / 属性 / 天赋各一档，折成一份 `OpeningLoadout` | L0（读 `stats` 的那几个键） |
| `slots` / `create` 两屏 | **选存档** + **捏人** | `game.ts` 的状态机各加一档 |

### 踩到的三个坑（都是"存档住在哪"这一类）

| # | 症状 | 根因 |
| --- | --- | --- |
| 1 | **`Storage.wipe()` 清不掉 1 / 2 号槽** | 它只删 0 号槽那三个键 + 备份。而"槽位 = 键重定向"这条设计的另一面正是"每个槽位各有一份键" —— 于是 `bronana.profile#1` **活过了 wipe**。表现：清空之后切到 1 号槽，上一段留下的档还在，而**不报错** |
| 2 | **`Profile.reset()` 会写到非 0 号槽** | 它现在会**写盘**（为了修第 3 条），而它没有钉住槽位 —— 停在 2 号槽上按"重置"，写出来的是 2 号槽的空档，0 号槽那位玩家的进度一点没动，他看到的却是"重置成功" |
| 3 | **"只清内存"的删除会复活** | `Profile.load()` 拿存储里那一份**覆盖内存**，所以"把内存里那个人删掉"在换一次槽位之后就回来了。实测：界面上"返回"清掉了人，切一下档他又在 |

第 1 条对测试的影响值得单独记：它让 `test/character.mjs` 的槽位隔离那一节
**以一个说不清的理由失败**（wipe 之后 `Slots.select(1)` 读出了别的用例写过的一份档）。
找它的过程就是"把每一句都打出来"——最后发现是**测试基础设施自己的洞**，
不是被测代码的。

### 顺手纠正的一处层次模型

`openings.ts` 要读 `Stats.KEYS` 校验属性键真的存在，而 `stats.ts` 当时在 **L1** ——
于是架构门报出一条**未登记的向上边** `mech→data`。两条路摆在面前：
去 `EXCEPTIONS` 登记一条理由（那份清单的注释写着"它越短越好"），
或者承认 `curves.ts` / `stats.ts` 本来就该在底下（依赖面只有 registry / selfcheck / utils）。

选后者。登记一条"只在两个纯函数表之间的向上依赖"，等于**为了让文件待在旧抽屉里
给架构加一条假边** —— 而那份分层模型自己写在注释里的纪律正是
"决定一个模块坐哪的不是它的性质，是它的依赖"。

## 二、批次二 · 对话补完（`63fde56`）

### 做了什么

R41 的普查结论是「对话有骨架缺一半」。八栏 ❌ 一次补完，
做法是**先认出它们的共同点**：那八样**都是时间的函数**
（一个字一个字地出、按住跳过、自动往下走），不是"再画一块界面"。
所以有了 `src/dialogue.ts` —— 一个**纯的**模块：不读时钟（`t` 由调用方喂）、
没有模块级可变状态、不认识 DOM。

| 补的那一栏 | 实现 |
| --- | --- |
| 打字机 | `Dialogue.indexAt(text, t)` |
| 点一下跳到整句 | `hubSay`：还在打的时候那一次点击就是"跳整句"（不记账、不换句） |
| 自动 | `Dialogue.autoDue` —— 露完再停 `HOLD_SEC` |
| 对话历史 | `pushHistory` / `recent`，上限 40 条 |
| 战斗短句 | `BARKS` + `barkFor(when, nth)` —— **按序轮转** |
| 选择 / 分支 | `story.ts` 的 `choicesOf` / `branchOf` |
| 玩家侧头像 | `playerCanvas`（用**这条存档的角色**，含第一批捏过的外观） |
| 跳过 / 自动 | 两个开关（不是一个三态） |

### 三条"看起来对、其实错"的写法（都留了守卫）

1. **短句用 `Math.random`** → 同一盘带子放出不同的话。
   `record.ts` 只录种子与逐帧输入，所以随机是**不可复现**的 ——
   而那不会报错，只会在某次回放时看到一句没见过的台词。
   做法：`_barkN` 记账 + `barkFor` 按表长取模。
2. **打字机按 `.length` 切** → 一个表情在 UTF-16 里是两个码元，
   切在中间就是界面上"半个字的方块"。做法：按**码点**，自检里拿 `'好🙂坏'` 逐长度切过一遍。
3. **在 `renderHub` 里推进打字机** → `renderHub` 被任何一次界面刷新调到，
   于是"重画一次就多打一个字" —— **帧率变成打字速度**。
   做法：计时放 `hallSync`（每显示帧一次），且只有"露出的字数变了"才重画。

### 顺手修掉的两处

- `diag.ts` 本来要 `import dialogue.ts` 取短句表长 —— `test/debug.mjs` 那条
  "诊断只读各系统的账、不依赖界面层"的判据**当场抓住**。改成走 `Game.barkTotal()`。
- 同一条短句连说两句时 CSS 动画不重播（动画挂在基类上）→ 改挂 `.on`。

### 一次**写明理由**的构建预算放宽

实测 723.88 kB，越过了 `chunkSizeWarningLimit: 720`。两条路：改那个数，
或者砍掉刚做出来的东西 —— 选了前者，并**同时收紧**真正要紧的那条
（gzip 270 → 275，实测 268.7）。

## 三、批次三 · NPC 交易（`0df7b18`）

### 做了什么

普查那句话说得很直：「**② NPC 交易系统：完全没有。**」这一批做出来，
而**唯一要想清楚的是它与商店的分界线**：

| | 商店 | 交易 |
| --- | --- | --- |
| 花什么 | `scrap`（战斗代币） | **`growth` / `material`**（§6.5 的硬约束） |
| 换什么 | 这一局的战力 | **下一局的开局条件** |
| 时间感 | 每一波刷新货架 | 每位商人每波限次 |

换**下一局**是刻意的：换这一局的战力会与商店重复（同一个功能两条路，
便宜的那条会废掉另一条）；换下一局才是养成模块该干的事。

### 抓到的真 bug：`bonds` / `talks` 只写不读

`run_save.ts` 从 M3 起就一直**写**这两个字段，而 `Game.importRun`
**从来没有读它们**。表现：刚跟菌母聊到「信赖」，读一次档回到「生人」，**不报错**。

它一直没被发现，是因为落在两个守卫的缝里：`flow` 门量的是
"**登记在案**的字段读回来还对不对"，而这两个字段**不在那份名单里**。

这条是"为了给交易加存档字段、顺路读一遍邻居"才撞见的 ——
**接线类的 bug 只有真的去接一遍才会露面**。

### 一条**永远不会红的检查**（写完当场发现自己写错了）

那条"收的代币必须是已登记的钱"的检查，第一版写在 `trade.ts` 的**加载期**。
而 `trade.ts` 比 `eco_*.ts` 先加载 —— **账本还是空的**，
于是 12 档报价被全部误报成"拼错了"，连 `material` / `growth` 都不认。

修法：只在"账本已接上电"时查（判据是 `Ledger.all().length > 0`），
真正的判据放在测试那一侧逐笔对账。

> 这条正好是 [`AGENTS.md`](../../AGENTS.md) 第三节那条纪律的**镜像**：
> 那里要求"自检必须证明它会失败"，而这里是"自检**误报**了"。
> 两者是同一件事的两面 —— **写完自检之后一定要真跑一遍**。

### 顺手修掉的三处

| # | 症状 | 根因 |
| --- | --- | --- |
| 1 | 一句文案在两处各有一份 | 引导那八句在 `tutorial.ts` 一份、`i18n.ts` 的英文表里再抄一份中文**当键**。改一处忘一处时那一句会**静默退回中文**（看着像没翻完）。现在文案住在 `I18n.TUTORIAL_TEXT` |
| 2 | `ui-check` 的选择器桩不支持复合类 | `.trade-row.off` 被当成"类名是 `trade-row.off`"→ **永远匹配不上**，而报出来的是"有 0 行标成不可做"——看起来像界面的问题、其实是**量尺的** |
| 3 | 引导文案里有 `**核心材料**` | 它是**渲染给玩家**的（HUD 飘字），星号会原样打出来 |

### 测试基础设施的一处让步（写清楚，免得下次以为是偷懒）

交易要求"站在他面前"，而枢纽是**真能走**的（`stepHall` + 碰撞）。
于是测试需要把人**摆到**某一站跟前 —— 为此开了 `Game._internals.placeHall(x, y)`
（只挪坐标，不碰任何玩法状态）。

理由是**两条路分开量各自才说得清**：

- "走过去真的能到" → `hall.ts` 的连通性自检 + `test/trade.mjs` [4] 一条**真走位**断言
- "站在他面前才能交易" → `placeHall` 摆好位置之后量钱扣没扣、货进没进下一局

第一版两个都靠在屋里走位，结果量到的是**另一个 NPC 的对话框** ——
断言红了，而红的原因是"测试不会走位"，不是代码错。

## 四、批次四 · 状态系统（R50 第 10 条）

### 做了什么

账本上这一条原文是「**没有独立模块**」，而"待确认 ③"问的是它与契约、
与 `game.ts` 里那些临时状态（无敌帧 / 狂暴 / 白闪）怎么分工。第四批先答了那一问：

| | 是什么 | 持续多久 | 谁给的 |
| --- | --- | --- | --- |
| **契约**（`boons.ts`） | 一层挑一次的**开局条件** | 整层 | 打完 Boss 挑 |
| **状态**（新） | **可叠层、有秒数**的 debuff / buff | 秒 | 命中 / 技能 / 道具 |
| 角色机制（`rage`）/ 受击无敌（`invuln`） | **命中的固有规则** | 由各自规则算 | 某角色 / 挨打那一刻 |

后两者**刻意不进表**：它们是**派生值**（`rage` 由已失生命推出来、`invuln` 由挨打
那一刻置位），没有"挂上去 / 掉下来"这回事。判据是"删掉这张表它们还成立吗" ——
成立，而且更好读。

顺带把**装备系统**那一条的判据**冻结**了（不新增独立槽位）：判据是
"删掉 `affixes.ts`，那五条词条还落在哪" —— 没有第二处该落的地方。

### 抓到的两个真 bug：`slow` / `stun` 是**死写入**

它们是这么写的：

```ts
case 'slow':
  e.slow = Math.max(e.slow || 0, (pr && pr.life) || 3);
  e.slowMul = Math.min(e.slowMul === undefined ? 1 : e.slowMul, 1 - ((pr && pr.slow) || 0.45));
  break;
```

而**全仓搜 `e.slow` / `e.stun` 只搜到这两处写入、一个读点都没有**。
于是「冰冻」与「打断」两个技能载荷**实际什么也没做**，界面上却写着它的说明。
第二个 bug 更隐蔽：这两个字段**没有在 `comp.ts` 里声明**（那里只有 `Burn`），
而**未声明字段不参与池化复位** —— 容器回收复用一只怪时，
上一只的 `slow` / `stun` 会**留在它身上**。

> 这条与前三批那四个 bug 是**同一个形状**：写在某处、没有任何读点。
> 所以顺手补了一条**静态判据**（`test/status.mjs` [6]）：
> 没有第二个模块可以自己**写**状态字段；直接**读**的模块逐行豁免、且**被数出来**。

### 本轮自己踩的三个坑（都是量出来的，不是猜的）

| # | 症状 | 根因 |
| --- | --- | --- |
| 1 | **定身期间怪还在滑**（20 帧漂 17.79 px） | 只把倍率乘到 `vx`/`vy`，而 `ai.ts` 里还有一套**击退残余速度** `kx`/`ky`。定身是"自己不能动"，击退是"被推" —— 两者都要按住 |
| 2 | **倍率加在了位置积分之后** | `AI.step` 返回时这一帧的位置**已经挪完**，在外面乘只是白乘一场。施加点移进 `AI.step`（积分前一步） |
| 3 | **层数想从"已消耗的时长"反推** | 满层的剩余时长与"刚挂上的 1 层"**可以相等**（被夹到上限时），反推分不开这两种情况。自检当场报"slow 叠了第二层而层数还是 1"，改成显式存 |

第 1 与第 2 条合起来说明一件事：**"改在哪一行"和"改对没有"是两件事** ——
两条都"看起来已经接上了"，而只有真的量位移才看得出来。

### 一处接线的妥协（写清理由，免得下次以为是偷懒）

`ai.ts` 的依赖面**只有** `utils` / `registry`（要什么能力都由 `AiCtx` 注入），
而 `test/ui-check.mjs` 有一条静态判据盯着这句话 —— 直接 `import status.ts`
当场报红（实测就是它抓到的）。所以倍率走 `AiCtx.statusMul` **注入**
（传的是函数引用，不是每帧现建的闭包），与 `ctx.spawn` / `ctx.shake` 同一条处置。

同一类处置还有一处：诊断面板第一版直接读状态字段，被 `test/debug.mjs`
（"诊断不依赖界面层"）与 `test/status.mjs` [6] **两条判据各抓了一次** ——
现在它只取 `Game.statusLine()` 那一行字。**两条独立的判据抓同一处，
说明那处确实越界了两条不同的线。**

### 指纹在这里的**边界**（本轮最值得记的一条）

第四批改了 `burn` 的实现（手写魔数 → 状态表）、还修好了 `slow` / `stun` 两个死写入，
而指纹**一点没动**。原因是那三个技能 / 元素在三条指纹用例里**都没有被触发**。

所以：**指纹证明不了"这次改动是对的"，它只证明了"没碰别处"。**
真正的证据是新套件里那两条断言。**指纹是必要的，不是充分的** ——
这个区别在改动落在"指纹覆盖不到的玩法路径"上时会骗人。

## 五、文档复核与四象限清点（2026-10-01）

用户这一条的要求是「检查文档，归纳整理，查漏补缺」+「检查需求清单，按四象限分类整理」，
并且**建议联网交叉补充、不要闷头造车**。做法与结果如下。

### 一、联网那条：先说清楚网络能到什么程度

**能用的**：搜索能返回标题与摘要。**取不到正文的**：`github.com`（`web_fetch` 直接失败）、
`en.wikipedia.org`（解析到非公网 IP 被拒）、Steam / `*.fandom.com`（环境本就不可达）、
`strayspark.studio`（HTTP 403 挡机器人）。这与 `docs/external-game-mechanics.md` 里
"保留取不到的记录"是同一条纪律 —— **不假装读过全文**。

于是四象限的**方法论来源**明确标了强度（只用了能打开标题与摘要的那几条）：

### 二、四象限怎么切的（轴是量出来的，不是挑词）

本项目的需求流是「用户提出 → AGENT 复述 → 讨论 → 动手 → 验证」，
所以真正卡住一条需求的东西只有两类。两个轴就取这两类：

- **轴一 = 是否需要用户先决策**（否 / 是）
- **轴二 = 对成品的影响**（可感知 / 不可感知）

| 象限 | 定义 | 条数 | 排期规则 |
| --- | --- | --- | --- |
| **I 着手** | 不用拍板 · 做完看得见 | **10** | 按依赖排序，占批次 |
| **II 决策** | **卡在用户身上** | **9** | **不排期**（排了也是空转） |
| **III 维护** | 不用拍板 · 玩家看不出来 | **15** | **并在任一批里顺手做**，不单独占一轮 |
| **IV 不做** | 写了理由的"刻意不做" | **3** | 只在"下次又被当成漏了"时引用 |

写进账本 [`docs/requirements.md`](../../docs/requirements.md) 的 **§6.0**（含每条的代价与正本指针）。

### 三、查漏补缺：**量出来的 5 处文档漂移**

复核用的是"文档说一个数 → 跑命令量同一个数"的对照法。漂掉的**全是最容易写死的四类数**
（行数 / 成员数 / 文件数 / 套件数）：

| 写在哪 | 文档里写的 | 实测 | 为什么会漂 |
| --- | --- | --- | --- |
| §五 R21 | `game.ts` 4108 → **3962** 行 | **5042** 行 | 那是**拆分当时**的数，之后 R50 四批与并行工作又往里加了 |
| §八 R28 | 约 **4.0k** 行 / ~**60** 个公开成员 | **5042** 行 / **113** 个接口成员 | 同上 |
| §八 R29 | 平铺 **72** 个 `.ts` | **94** 个（**93** 模块 + `types.d.ts`） | 后续批次新增了 20 余个模块 |
| §五 R08 | **53** 套测试 | **63** 套 | 套件数是"从清单算出来"的那个，正文那份是旧值 |
| §五 R01 | `affixes.ts`（**792** 行） | **868** 行 | 词条链加深时长的 |

**没漂、逐位复核过的**（写下来，因为"没漂"也是结论）：三个行为指纹（与
`test/smoke.mjs` 的 `CASES` 逐位一致）· 门 **17** 道 · 套件 **63** 套 · 模块 **93** 个 ·
家族 **137** 个 · 依赖环 **0** · 向上的边 **2** 条 · 运行时依赖 **0** · 素材 **0** ·
`new Image()` **0** 次 · `fetch`/`WebSocket`/`XMLHttpRequest` 在 `src/` 里 **0** 次。

处置：**不逐处改那 5 个数**（改完还会再漂），而是在 §十一 的基线表下面加了一张
"**哪几条漂了、漂成什么**"的对照表，并把真相钉在"上面那张表 + 命令输出"上。
另把 `AGENTS.md` 里真正过期的三处直接改了（模块/行数、套件数、以及**一道不存在的门**：

> `AGENTS.md` 第十节第 7 条原文写"手写硬编码颜色会被 `hardcode` 与 `PAL` **两道门**抓"，
> 而 `tools/` 下**没有任何颜色门**（`hardcode-audit` 的三条判据全是算术式与格式化配方，
> 匹配不到颜色，而且它整文件排除渲染层）。**门不存在、文档却在指认它** ——
> 这正是账本 A13 ② 记的那一条。改法不是把门"说"出来，而是**把这句改成实话**

## 六、这一卷里反复出现的两件事

**① 每个 bug 都落在某个守卫的射程之外。**
批次一的三个是"槽位键"，批次三那个是"不在存档字段名单里的字段"，
