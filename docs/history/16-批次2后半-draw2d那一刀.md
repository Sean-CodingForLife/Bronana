# 16 · 批次 2 后半① —— `draw2d` 的最后一刀

## 一、为什么是这一刀

门 `engine-boundary` 把 `draw2d.ts` 判成**混合**：原语层是引擎，但同文件里夹带了一层内容语义。
它的 note 写着两刀：

1. **命名那一半** —— E3 第 1 小步已还清（`bronanaPath` → `seedBlobPath` 等）；
2. **「眼睛 / 嘴 = 表情」这一层语义** —— 本轮这一刀。

`eye` / `mouth` 不是引擎原语：引擎只知道"画一个椭圆 / 一段弧"，**不知道"这是眼睛"**。

## 二、搬到哪：`bronana.ts`（不是 `sprites.ts`）

| 候选 | 判据 |
| --- | --- |
| `sprites.ts` | ❌ **会成环** —— 它**已经** import `bronana.ts`（架构门禁环） |
| `bronana.ts` | ✅ 调用者全在内容侧（`bronana.ts` 6 处 + `sprites.ts` 8 处），而且"脸"本来就是**角色**的语义 |

## 三、搬出来才暴露的三件事（都是门抓的，不是我想到的）

1. **`typecheck`**：搬走的代码要用 `ctxOf`（把 canvas 归一成 **RHI 包装过的 ctx**）与 `O`。
   `O` 本来就导出了（`D.O`）；`ctxOf` 是模块内的 —— 但它是**通用能力**，
   所以按 **content → engine** 的方向**导出** `D.ctxOf`，**而不是复制一份**（复制 = 两份真相）。
2. **`typecheck`**：还有一处裸的 `fill(` ⇒ `D.fill(`。
3. **门 `hardcode`**：`r * 0.1` 与 `w * 0.55` **各自在同一个函数里出现 3 次** ——
   搬家之前它们分散在两个文件，所以**从来没触发过**；搬过来才暴露。
   ⇒ 提成局部量 `dy` / `wx`（**一个量、一处表达式**）。

## 四、两条流程教训（比这一刀本身值钱）

1. **上一轮修的 `dev-edit` 原子性，这一轮真的救了第二次。**
   我先用手打的长整行当锚点，3 处对不上 ⇒ **整份 patch 一个字节都没写**（`typecheck` 报的正是
   "脚本搬完、收尾未做"的原状）。**上一轮同样的情形把源码改坏了**（拿到半应用的源码，
   报 `dy`/`dy2`/`dy5` 找不到）。有这条保证，"试错"才敢做。
2. **手打长整行是脆的 ⇒ 改用带护栏的正则脚本。**
   `r * 0.1` 是 `r * 0.15` / `r * 0.12` 的**前缀**，字面 `replaceAll` 会把它们一起吃成 `dy5` / `dy2`
   —— 这正是上一轮流血的根因。正确写法是 **token 守卫**（前后不许是数字/点）。
   还有一条**顺序**：**先替换使用点，再插入局部量声明**，否则声明行自己会被替换掉。
