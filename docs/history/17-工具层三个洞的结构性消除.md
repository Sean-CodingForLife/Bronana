# 17 · patch 层的三个洞

## 一、用户的问题，与我的自查

用户的原话是：**「这几轮里你一直反复的遇到了几个问题，有没有想过彻底的解决掉，
而不是一直转圈」**。这个判断是对的，下面是数出来的账：

| 那 11 轮里的时间去了哪 | 量 |
| --- | --- |
| 真功能提交 | 3 个（工作区清单 · 内容显式认领 · `draw2d` 那一刀） |
| 真基础设施提交 | 2 个（`dev-edit` 原子性 · 那条断言） |
| 纯记录 | 3 个（history / CHANGELOG / requirements） |
| **净浪费** | **≈3 轮**，全部来自同一类事：**patch 没写进去** |

而根本原因不是"我不小心"，而是**我把教训写成了注释**。
本仓库家法第一条写得很清楚：**凡是靠人记住的规范，都会漂** ——
而我当时做的恰恰是"记在注释里、下次注意"，也就是**我自己违反了这条家法**。
所以这一轮的判据是：**这三类错误，能不能变成"不可能发生"或者"发生时当场自证"？**

## 二、三个洞（都真有声音之前的形状）

| # | 形状 | 真实发生 | 代价 |
| --- | --- | --- | --- |
| P1 | patch 的 JSON 字符串里混进**没转义的 ASCII 双引号**（中文文案里极常见） | 一轮里 **6 次** | 整份 `JSON.parse` 被拒 ⇒ **每次白烧一轮** |
| P2 | **手打的长锚点**与文件里真实文本差一点点 | **3 次** | 工具只说"一次都没命中"，**等于没给任何线索** |
| P3 | `replaceAll` 的 `from` 是更长文本的**前缀**（`r * 0.1` 咬到 `r * 0.15` / `r * 0.12`） | 1 次 | **把源码改坏**（`dy5` / `dy2`），而且**毫无声音** |

前两个是"浪费一轮"，第三个是"改坏代码"——它们共同的形状是：**失败没有信息量**。

## 三、处置：让错误不可能发生，或者当场自证

| 洞 | 现在怎么办 |
| --- | --- |
| P1 | **`--patch-js`**：patch 写成 `.mjs`、文本用反引号包住 ⇒ **零转义**（引号、中文、反斜杠都不碰）；仍然写 JSON 时，报错**指出第几行第几列**、把那一行与插入符打出来，并点明这是 P1、给出两条出路 |
| P2 | 失败的 op 会**自己去文件里找最接近的几行**（双字组 Dice 相似度 + 子串探测剥洋葱）并列出行号与原文 |
| P3 | ① 每一处命中都打**行号与上下文**（以前只说"命中 N 处"）；② 命中边界**紧邻标识符/数字字符**时**默认拒绝**（退出 1、不写盘）；③ 要过必须 `"word": true`（自动整词护栏，`r * 0.1` 便不再匹配 `r * 0.15`）或显式 `--allow-risk` 认账 |

一句话原则：**看不见的替换就是危险本身** —— 工具改成"宁可吵，不可静默"。

## 四、证据

- 门 `test:dev-edit`：**27 → 46 条断言**。新增的 19 条里，P1/P2/P3 三节**全部先注入真的坏输入**
  （真的坏 JSON · 真的对不上的锚点 · 真的会前缀碰撞的 `r * 0.1`），再证明它会红 ——
  家法：**一条不会失败的审计等于装饰**。
- `pnpm verify`：**28 / 28 全绿 · 223.6s**；本次不碰 `src/`，行为指纹未变。
- 自曝一处：`--allow-risk` 的那条断言，断言的就是**这个坑的形状**
  （`r * 0.15` 真的被写成 `Q5`）—— 把它写进测试，是因为"允许它发生"这件事本身要有证据。

## 五、这一轮**量**出来的两件事（不是猜的）

### 1. `verify --changed` 的收益比想的小 ⇒ 这一轮**不做**

把 28 道门的输入逐个读了一遍：**22 道门的输入含 `src/**`**，
所以**任何 `src/` 改动几乎等于全量**，`--changed` 只对"只改 docs / tools / .github /
`workspace/*.json` / `index.html` / `styles.css`"这类改动有效。
真正拖时间的场景（批次 ③ 要动几十个 `src/` 文件）它**帮不上**。
⇒ 先不做；这份"门 → 输入"普查留着，等有真实数据再决定。

### 2. 「新增一个 `src/` 模块要登记几处」：**15 处会红，11 处静默**

把登记点普查了一遍，其中最重的一条：

> **门 `engine-boundary` 的三张分类表没有门守着。**
> 一个新模块**一个字都不写**，只会进提示级「既不是引擎、也不在数据表清单里的模块 N 个」，
> `problems` 为空、**退出码 0**。也就是说——**"它算引擎还是内容"可以永远不写下来而全门全绿**。
> 门自己的注释承认：批次 2 之前有 35 个内容模块一直处于这个状态。

这与本轮的目标（引擎 / 内容分离）**直接相关**：分离这件事的**判据本身**没有门。
另外 11 处静默里还有：`_load.mjs` 的第二个清单（`SIM_MODULES`）漏了不红；
`CONTENT` / `DATA_TABLES` 里写了盘上不存在的文件不报（只有引擎那两张表查了幽灵条目）。

## 六、下一轮（这一轮没做完的）
