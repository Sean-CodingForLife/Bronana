# 21 · 无感知（E4 批次 0）

**用户口径**：「所有和 Bronana 有关系的**统统**移动到 Bronana 自己的工作区里去，
二者要**彻底分离和无感知**。」

这个仓库里"引擎认识内容"的证据不是目录，而是**这四行**：
`src/main.ts` / `src/cli.ts` / `test/_load.mjs` 的 `Storage.setNamespace('bronana')`
与 `storage_fs.ts` 里写死的默认存档目录 `~/.bronana`。**目录可以明天再搬，
认知不搬走就什么都没解决** —— 所以这一批排在 `git mv` 之前。

## 一、改成了什么（一条纪律，三处落地）

| 处 | 之前 | 现在 |
| --- | --- | --- |
| `src/cli.ts`（Node 宿主） | `Storage.setNamespace('bronana')` · `defaultSaveDir()` | **发现清单 → 读盘 → `Workspace.parse` 认 → `Workspace.set`** ⇒ `Storage.setNamespace(Workspace.namespace())` · `defaultSaveDir(Workspace.id())` |
| `src/main.ts`（web/桌面宿主） | 同上（写死） | 浏览器读不到磁盘 ⇒ 构建期由 `vite.config.ts` **发现清单并 `define` 进包**（`__TEAPOT_WORKSPACE__`），`main.ts` 交给引擎认；**缺失/不合法 ⇒ 走崩溃卡**（可见的失败，不许悄悄退回某个工作区） |
| `test/_load.mjs`（测试宿主） | 同上（写死） | 与 `cli.ts` 同一条路（它是 Node 宿主）；读不到就**抛** |

`src/storage_fs.ts` 新增：`repoRoot()` · `workspaceFiles()`（发现，按路径字典序 ⇒ **顺序确定**）·
`readManifest()`（解析失败就抛）· `defaultSaveDir(id?)` ⇒ `~/.<id>`，**`id` 缺省时退到中性的
`.teapot`**（不许在这里写死任何具体工作区的名字）。

## 二、判据（门 `workspace` 第 5 条）

> **`Storage.setNamespace(x)` 的 `x` 不许是字面量**，而且调它的宿主里必须真的出现"读清单"
> （`Workspace.namespace()` / `workspaceFiles()` / `readManifest()`）。

⚠ 这条判据**只判形状**（实参是不是字面量），**不比对该字面量等不等于清单里的 `id`** ——
因为问题从来不是"值写错了"，而是"**有第二个出处**"（值恰好写对了的字面量一样是第二个出处）。

自证扩到 **11 条**，其中三条是这一批的：① 命名空间写成字面量 ⇒ 红；② 调了 setNamespace
却没人读清单 ⇒ 红；③ **好形状**（`Storage.setNamespace(Workspace.namespace())`）⇒ **不许报**
（防"判据太饿"：只会红的判据最后没人信）。

## 三、这一批**没有**做的事（写下来，免得被当成做完了）

- **目录一个字节都没搬**（那是批次 2）：`entry` / `content.src` 仍指向仓库根的 `src/`。
- **混合档那 4 个没切**（`draw2d` / `comp` / `audio` / `music`）—— 那是批次 2 的**前置**。
- **`workspace/` 下多份清单**时 `vite.config.ts` 直接报错（"一个构建绑一个工作区"）：
  真正的多工作区切换（`?workspace=<id>` / 宿主注入）是**批次 1** 与账本 §13.3 的待决项。
- **旧名兼容没动**：`BRONANA_HOME` / `BRONANA_SOURCEMAP` 仍然读（改名只改一半是家法里的坑）。
