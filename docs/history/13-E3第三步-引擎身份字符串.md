# 13 · E3 第 3 小步 —— 引擎身份字符串

> 这是 E3 的收尾。前两小步还清的是门 `naming` **看得见**的那 17 处；
> 这一小步清的是**门外**那六类里的五类 —— 门**扫不到**它们（门只扫 23 个引擎模块，
> 而 `cli.ts` / `crash.ts` / `main.ts` / `tools/**` 都不在清单里）。

## 一、改了什么

| 类 | 改前 | 改后 | 为什么 |
| --- | --- | --- | --- |
| CLI 自称 | `'Bronana 命令行'` · `'=== Bronana 无头跑局 ==='` | `Teapot …` | 命令行是**引擎**的工具，它自称的应该是引擎 |
| 运行时日志位 | `'[Bronana] 运行时错误（'` | `'[Teapot] …'` | 同上（引擎的运行期日志） |
| 自检失败框 | `'Bronana 启动自检未通过…'` | `'Teapot …'` | 那是**引擎的表**坏了（文案自己写着"这是代码里的表有问题"） |
| **崩溃卡（给玩家看）** | `'Bronana 出了点意外…'` | **`'出了点意外…'`（中性）** | ⚠ 见下 |
| 工具横幅 | 29 个文件里的 `=== Bronana · X ===` | `=== Teapot · X ===` | 跑门第一眼看到的就是它 |
| git hook 标记 | `# >>> bronana pre-commit …` | `# >>> teapot pre-commit …` + **认旧标记** | 已装过的人不能被当成"别人的 hook"拒绝覆盖 |
| 第三只环境变量 | `process.env.BRONANA_HOME` | `TEAPOT_HOME \|\| BRONANA_HOME` | 与 E2 的 `SOURCEMAP` 同一条规矩：**旧名不许静默失效** |

### 崩溃卡为什么**刻意不写名字**

那张卡是给**玩家**看的，而玩家玩的是**某个工作区**（今天叫 Bronana）——
**引擎不认识它的名字**。所以这里不给它贴任何一个名字，用中性措辞；
**E5 之后由工作区清单的 `displayName` 注入**。
理由写进了代码注释：贴「Teapot」对玩家没意义，贴「Bronana」又是引擎在自称游戏 ——
而后者正是门 `naming` 与用户那句「不要混了」要拆的东西。

## 二、两处**被测试断言钉死**的（先改判据，再改字符串）

家法：**判据里的旧值要跟着被测对象一起改**（这条在 E2 已经栽过一次：`BRONANA_SOURCEMAP` 被断言写死）。

| 判据 | 改前 | 改后 |
| --- | --- | --- |
| `test/modes.mjs:304` | `/Bronana 命令行/` | `/Teapot 命令行/` |
| `test/audio.mjs:342` | `/Bronana 出了点意外/` | `/出了点意外/` |

## 三、⚠ 我在这一轮犯的两个错（都记下来）

1. **横幅脚本改多了**：我写的替换脚本顺着 `tools/` **和 `test/`** 一起走，
   于是把 `test/` 里 **64 份套件标题**的 `=== Bronana · X ===` 也改了 ——
   而**上一轮的账本里明确记着"那些标题说的是被验的内容，故意不动"**。
   已用 `git checkout -- test` 撤回那 64 处（先确认每个文件只差那一行），
   只保留 `tools/` 的 29 处。
   **教训：改名脚本的作用域必须跟"谁是引擎、谁是内容"的判据对齐**，
   否则它会**越界去改内容的名字**。
2. **patch 的 JSON 里三次混进 ASCII 双引号**（`"引擎自称某个游戏"` / `"别人写的 hook"` / `"不要混了"`），
   `dev-edit` 三次都**拒绝整份 patch、一个字没写**（这正是它比 shell 安全的地方：
   shell 的 `.Replace()` 不命中时**静默成功**）。
   **教训：写 patch 时引用一律用「」**，别用 ASCII 双引号。
