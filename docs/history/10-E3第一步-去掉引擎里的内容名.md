| `src/draw2d.ts` | `bronanaPath` · `D.bronanaPath` · `D.bronana` | **`seedBlobPath`** · `D.seedBlobPath` · **`D.seedBlob`** | 它画的是"一个 30 点、被种子调制的团形"，**与豆豆无关**；`seedBlob` 点出「种子调制」这个区别特征 |

## 二、⚠ 动手前才查出来的两个坑（这才是本卷值钱的部分）

### 坑 1：**计划里的新名字会撞名**

`naming.mjs` 的还款计划写的是"改名 `blobPath` / `D.blobPath` / `D.blob`"，
`docs/teapot-restructure.md` 也照抄了同一句 —— 而**动手前查了一遍 `draw2d.ts`**：

```
draw2d.ts:66   function blobPath(x, pts, r, close)      ← 早就存在（D.blob 的路径助手）
draw2d.ts:230  D.blob = function (c, pts, r, color, o)  ← 早就存在（点列表团形）
```

**两个目标名字全被占用了** —— 照计划改会直接撞出一个语法错误（或更糟：静默覆盖一个原语）。
⇒ 改用 **`seedBlob` / `seedBlobPath`**，并把两份文档里的计划**一并更正**。

> 教训：**"计划里写的名字"不是判据，源码才是。** 改名前先 `grep` 一遍目标名字，
> 成本 10 秒；撞名的代价是一次静默覆盖。

### 坑 2：**门自己的自证测试被写死了，于是它"绿着红"**

改完跑全量，**23 / 25 门**：`test` 与 `readme` 红。`test` 红在
`test/naming-gate.mjs`（门 `naming` 的自证套件）：

```
FAIL 实测多于表 ⇒ 退出码 1  → 得到 0 · 期望 1
FAIL 实测少于表 ⇒ 退出码 1  → 得到 0 · 期望 1
```

根因：那套测试用 `s.replace("'comp.ts': 1,", …)` **给自己的探针取值**，
而本步**把 `'comp.ts': 1,` 还清并删掉了** ⇒ `.replace` **匹配不到就静默不改** ⇒
门当然是绿的，测试却报"期望红"。

> 🔴 这与本项目记过的「**改名只改一半 / 判据里硬编旧值**」是**同一个坑**
> （E2 那次是 `BRONANA_SOURCEMAP` 被断言写死）。
> **修法不是把 `comp.ts` 改成 `storage.ts`**（下一次还清又会重演），而是让探针**自己造**：
> 往 `DEBT` 里注入一条合成欠账（`'fold.ts': 0` / `'fold.ts': 2`），
> 于是**表变短、乃至表被清空成 `{}`，这套自证仍然有效**。
> 顺带补上了"方向 A 也要验证还原"这一条（原来只验了方向 B）。
