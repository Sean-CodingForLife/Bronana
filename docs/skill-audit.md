# 行业判据自检清单（skill 体检）

> 这份文档把**引擎无关**的游戏开发判据逐条对着本项目检查，输出"达标 / 部分达标 / 未达标"。
>
> ## 为什么用 skill 当判据
>
> 这份仓库有自己的校验（`pnpm verify` 的 13 道门），但它们量的是**内部一致性**
> （表 ↔ 运行时、家族有没有守卫、死代码…）。它们回答不了"**行业上这件事该怎么做**"。
> skill 里的清单正好补这一半：它们是**外部判据**，而且刻意写成引擎无关。
>
> ## ⚠ 适用面：本项目不用任何游戏引擎
>
> 本机 skill 目录里 **50 多个是引擎专用**的，**一条都不适用**：
>
> | 不适用的类别 | 例子 | 为什么 |
> | --- | --- | --- |
> | Godot | `godot-*`（14 个） | 本项目没有 `.tscn` / GDScript / `Node` 树 |
> | Unity | `unity-*`（8 个） | 没有 `MonoBehaviour` / `.asset` / `Animator` |
> | Unreal | `unreal-*`（6 个） | 没有 Blueprint / `.uasset` / Niagara |
> | Roblox | `roblox-*`（6 个） | 不是 Roblox 平台 |
> | 其它引擎 | `phaser-*` / `pixijs-*` / `threejs-*` / `bevy-*` / `love2d-*` / `pygame-*` | 不是这些框架 |
> | 具体引擎的输入/音频/瓦片 | `unity-input-system` / `godot-audio` / `godot-tilemap` … | 同上的引擎 API 绑定 |
>
> **适用的是"引擎无关"的那 9 个**（下表）。它们的判据是**做法**（分层、总线、
> 屏幕栈、池化、种子化），不是 API —— 所以对本项目的纯 Canvas 实现照样成立。
>
> 另外两个 `unity-scriptableobjects` / `godot-resources` 的**数据驱动思想**与本项目
> 的"声明表 + 注册表 + 自检"高度同源，但项目已有自己更严的一套，故不单列。

### ② `input-systems`

| 判据 | 状态 | 证据 | 差距 |

| 设备切换时提示跟着换 | ❌ | `Input.padInfo()` 只回答"连没连"（设置页用），**没有任何地方按当前设备切提示** | 键位提示在帮助页与设置页都是键盘写法。手柄玩家要自己把"空格"翻成"A"。要修得先有"最近用的是什么设备"这个状态 |
| 可访问性（不强制同时按/灵敏度） | ✅ | 十个热键全是**单键**（无组合键）；`settings.ts` 有 `fontScale` / `reduceMotion` / `shake` | 手动模式本身需要同时操作移动 + 瞄准 + 开火 —— 那是**模式选择**而不是强制（自动模式一个人都不用按） |

| 判据 | 状态 | 证据 | 差距 |
| --- | --- | --- | --- |

| 自动播放被拦的兜底与提示 | ✅ | `Sfx.resume()` 返回是否 running 并置 `blocked`；`Input.onPadGesture` 覆盖**纯手柄玩家**（Gamepad API 不发 DOM 事件） | `blocked` 的界面提示文案仍靠 toast（没有常驻指示） |

| 自检 / 家族登记 | ✅ | `audio.ts` 与 `music.ts` 都补齐这四步（`LIST`/`audit`/`SelfCheck.register`/`Registry.family`） | — |

| 屏幕震动用衰减 trauma 而非每帧随机 | ✅ | `R.addTrauma(a)`：trauma ∈ [0,1]、**幅度 = trauma²**（收尾干净）、`SHAKE_DECAY = 2.4/s`；同一帧多次请求取 `max` 而不是累加（火箭筒的高频事件不会顶到永久晃动）。**唯一四个请求点**：玩家受击 0.50 / Boss 倒下 0.9 / 自爆怪 0.30 / 爆炸 0.20~0.34（暴击更重） | — |
| **命中定帧（hit-stop）** | ✅ | 做成设置项 `hitStop`（档位 `off/light/medium/heavy` = 0/2/4/7 帧），**默认 0 = 关**；实现是"缩短这一步的位移"（`moveDt = dt * hitStopScale`）而不是跳过整个 `step()`（后者会让子弹与计时器一起停 = 掉帧）。**只在精英/Boss 上触发**（打杂兵也定帧会让高射速配置变成"一直在定格"）。判据在 `test/feel.mjs`，落在**逐帧位移**上（总位移差测不出来） | 默认关是刻意的：会改模拟时序的东西必须显式选择，否则"纯重构逐位不变"这条判据就没了 |

| 反馈按重要度分级 | ✅ | 四级，靠**触发条件**分级而不是靠音量：① 普通命中（6 层，最轻）；② 击杀（+碎片 +大血迹）；③ 精英命中（+定帧）；④ 玩家受击 / Boss 倒下（+抖动 0.5 / 0.9）。音频侧独立还有一层**闪避**（`Sfx.DUCK_FOR`：爆炸/升级/清波/开波/受伤/购买会把音乐压到 35%） | — |
| 可访问性：减少抖动/闪烁 | ✅ | `reduceMotion`（把 `R.shakeScale` 直接归零，**与抖动滑条无关**）+ `shake` 倍率滑条 + `?nofx` 类调试开关 | 原名"没有此设置项"是**过时记录**（收尾轮批次 A 第 3 条已经补上了） |

### ⑨ `game-ai`

| 判据 | 状态 | 证据 | 差距 |
| --- | --- | --- | --- |
| 有决策层（FSM/BT） | 🟡 | `ai.ts` 是**行为注册表 + 数据绑定**，不是 FSM/BT：`AI.behaviour(name, {move, contact})` 注册函数对，怪物的 `def.behavior` 按名字查表（`BEHS[def.behavior]`，查不到**当场抛**）。每条行为自己读"到玩家的距离 + 朝向"算速度意图（`chase` 直线贴脸 / `ranged` 保持 `keepDist` 并环绕 / `boss` 压上） | 状态存在组件的 `t1`/`t2`（**声明过**的字段，不是临时挂）；三个"换应对方式"的 Boss（`burrow`/`summon`/`metronome`）在这套原语上写了状态机。**没有** BT / Utility / 黑板 —— 对一个"成百上千只杂兵 + 少数精英"的割草游戏，它们是过度设计（每条行为只需要回答"往哪走、什么时候出手"） |

### 批次 C —— 收尾轮新增的三条校验（都不是"加功能"，是"让质量可验证"）

11. **硬编码体检** —— `tools/hardcode-audit.cjs`。判据**不是**"源码里有几个数字"
    （那个数毫无意义：渲染层里 `6/8/12/16` 各出现几十次，因为它们是像素几何量），
    而是"**同一个概念被写了几遍**"：同一文件里重复的算式 / 跨文件的同一语义算式 /
    重复的格式化配方（并排除渲染层）。基线只能变小。
12. **SOLID 体检** —— `tools/solid-audit.cjs`。五条各自翻译成能当场量出来的形状，
    见 `README` 的那张表。写它的过程本身就是证明："我们符合 SOLID"这句话

13. **README 存量表对账** —— `tools/readme-stats.cjs`。那张表**漂过**
    （写着 `game.ts` 3446 行 / 55 个模块 / 扇入 33，实测全不是）。
    漂了的统计比没有统计更糟：它看起来是量过的。
14. **音效调用普查** —— `tools/audio-census.mjs`（`pnpm run audio:census`，`pnpm verify` 的第 17 道门）。
    补的是 `Sfx.audit()` **验不了的那一半**：它只验"声明过的 id 都挂了函数"，
    验不了"**声明了却没有任何调用点**"—— 而后者才是真正的失败模式
    （`Sfx.waveStart` 是个完好的函数，但没人调它 = 那件事没声音）。
    四条判据：① 每个声明过的音效至少有一个调用点；② 模拟层广播的意图入口必须接上；
    ③ 意图名必须是真实音效函数；④ 调用点指向的音效必须存在（抓错字）。
    它还顺手把每个音效的调用点分成三档（**模拟层广播** / 事件名 / 界面手点）——
    这三档给的保证不同，混在一起会让"音效覆盖率"看起来比实际弱。
    写它的过程里栽了两个坑，都写进文件头了：**没去注释**（`audio.ts` 自己那句
    "改造前是模拟层直接 `Sfx.kill()`"的注释被当成了调用点，于是真问题报成了绿的）、
    **没去 `\r`**（Windows 上块级正则全部匹配不上）。
