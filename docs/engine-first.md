# 引擎优先：为什么"内容用不上"不是否决引擎能力的理由

> 这份文件是**判据文档**，不是设计文档。它只回答一个问题：
> **面对一条"某某引擎都有"的能力，该用什么判据决定做不做？**
>
> 用户原话（反复强调过三次）：
> 「我提出的很多需求**本质上是为了游戏引擎的开发而提出的**，你似乎每次都在用
> **现有的游戏内容**去做测试和推算合不合理，但实际上我一直强调的是，
> **先有游戏引擎再有游戏内容**，游戏内容和游戏引擎是**解耦的、是两个不同的东西**，
> 然后**一个游戏引擎该有的我要有**，你得**查漏补缺为未来铺路**，而不是只看现在怎么样」；
> 「现在的游戏内容部分做的**远远不够**，所以你现在**安心把游戏引擎做好、做优秀**，
> 我才能再全面开展关于游戏内容的开发，而且也是**基于游戏引擎**的」；
> 「游戏引擎要**抽象化**，要符合 **SOLID 原则**，**不要和游戏内容耦合**，
> 要**工程化、模块化、系统化**」；「**自研工具、自研框架、自研模块**，
> 这些都是**在为游戏引擎开发铺路，要做好地基**」。

---

## 一、被明令禁止的那条判据

🚫 **"现在的游戏内容用不用得上"** —— 不许再用它否决任何引擎能力。

它为什么看起来有道理、其实是错的：

| 它的样子 | 错在哪 |
| --- | --- |
| "本作**零素材** ⇒ 没有解码层，所以资源加载 Worker 不做" | **零素材是内容侧的一个选择**，不是引擎缺少"资源管线"的理由。引擎要能加载素材；**这个项目现在选择不用素材**，两件事 |
| "模拟层中位 0.700ms ⇒ 物理 Worker 不值得" | 现在的内容只有几百个圆。**引擎的并行能力不该由"当前实体数"决定** |
| "本作**已刻意不做寻路** ⇒ 寻路 Worker 不做" | **内容不用寻路**，不等于**引擎没有寻路**。将来加一间走廊房就要它 |
| "纯 2D **无骨骼** ⇒ 动画 Worker 不做" | 同上：没有骨骼是**内容形态**，不是引擎不该有骨架/时间轴抽象 |
| "渲染提交不是瓶颈（305 次/帧）⇒ 渲染抽象层不必急" | **R49 已经拍板换 WebGL2** —— 而后端抽象层正是"换得动"的前提。用现在的绘制次数去论证"不必抽象"，等于用内容否决引擎 |

**一句话**：上面每一条的**前提都是内容**，而结论却是关于**引擎**的。
这正是用户说的"**耦合**"—— 把内容的状态当成了引擎的判据。

---

## 二、现在该用的判据

✅ **"一个游戏引擎该不该有这条能力"** —— 判据来自**引擎侧**，不来自内容侧。

具体分三问，**按顺序问**：

### 问 1：这是**引擎能力**还是**游戏内容**？

| 是引擎（该有、且要与内容解耦） | 是内容（属于这个游戏，不属于引擎） |
| --- | --- |
| 渲染后端抽象（RHI / Target / Pass / 批处理） | "豆豆是圆的、有眼睛" |
| 空间查询与碰撞的形状/阶段（宽相 / 窄相 / 射线 / 层掩码） | "这个怪 120 血、掉 3 个废料" |
| 时间 / 循环 / 场景栈 / 事件总线 | "第 10 波开始刷精英" |
| 资源管线（加载 / 缓存 / 引用计数 / 释放） | "本项目的素材是零" ← **这是内容选择** |
| 对象系统 / 属性系统 / 序列化 | "`bulwark` 是壁垒" |
| 输入映射与重绑定 · 音频总线 · 存档框架 | "按 R 换弹" |
| UI 框架（布局 / 交互 / 焦点） | "据点屏长什么样" |
| 作业系统 / 工具链 / 自研框架 | "地牢有几层" |

**判据的可操作形式**：问一句「**把它原样搬到一个完全不同的 2D 游戏里，还能用吗？**」
—— 能用 = 引擎；不能用 = 内容。（这与 `tools/engine-boundary.mjs` 的"可替换性"是同一条。）

### 问 2：它**已经是引擎的**吗，还是**只是替这个游戏写了**？

这一问专门抓"**看着像引擎、其实是内容**"那一类。例：
`D.ditherBand`（抖动排线）**是引擎**（任何 2D 引擎都该有的填充原语），
而"用抖动画出荒漠地面"**是内容**。同一件事的两半要能分开 ——
**分不开就是耦合**。

### 问 3：**未来**会不会要？

用户的原话是「**哪怕你认为现在不需要，但未来呢**」。
所以最后一句永远是：**如果将来要，现在这个结构挡不挡路？**
- **不挡路** ⇒ 记为引擎能力，排期；
- **挡路**（要重构才能加） ⇒ **现在就要把抽象做出来**，哪怕它是空实现。

---

## 三、⚠ 唯一真正的约束：抽象不能是**没有调用方**的死代码

这条约束**不是**"内容用不上就别做"，而是**"抽象必须被证明是可用的"**。
本仓库的 `arch-audit` 会报**死代码**，`guard-gaps` 会报**没人守的家族** ——
所以空抽象会被工具点名，这是**真约束**，不能装作不存在。

**解法（这才是"为未来铺路"的正确形态）**：**引擎能力包（capability kit）**。

> 一条引擎能力 = ① 抽象与接口 + ② 至少一个**规范示例**（canonical sample）
> + ③ 它自己的测试（证明抽象真的能用、且不依赖本作内容）
> + ④ 注册进总账（`Registry.family`）+ 四步齐全。

**关键区别**：这个"示例"**不是本作的内容**，而是**引擎的开发工具**——
它在 `test/` 或 `tools/` 里，用**一个与豆豆无关的假对象**跑通抽象。
它同时证明三件事：
1. 抽象**有调用方**（工具不会报死代码）；
2. 抽象**真的通用**（示例不依赖本作内容 ⇒ 这就是 SOLID 的"可替换"）；
3. 抽象**将来接内容时不用重构**（示例就是"一个新游戏"的最小版本）。

这与本仓库已有的做法**同构**：`test/_ctx.mjs` 的 Canvas2D 桩、`tools/game-kit.mjs`、
`demo.ts` 都是"不是内容、但让引擎可被验证"的东西。

## 四、❌ §九 的「刻意不做」并没有失效 —— 但要注意它记的是什么

`docs/requirements.md` §九 的条目（联网 / 多人 / 寻路 / 素材 …）**多数是"这个游戏的
设计决定"**，那是**内容侧**的决定，写在账本里是对的。

**要小心的只有一处**：一条能力**同时**是"内容不需要"**和**"引擎该有"时，
**不许**用前者把它记成 ❌。逐条复核：

| §九 的条目 | 它是内容决定还是引擎能力？ | 处置 |
| --- | --- | --- |
| 联网 / 多人 | **内容决定**（这个游戏是单机） | ✅ 保留 ❌，但**理由要写准**："引擎不提供网络层"**不能**由"本作单机"推出；正确写法是"**本作的网络层不做**，引擎侧留接口" |
| 寻路 | **内容决定**（这两张图不需要） | ⚠️ **要改**：引擎该有寻路/导航抽象（网格图 + 查询接口），本作**可以不用** |
| 素材 / 图片 | **内容决定**（本作选择全程序化） | ⚠️ **要改**：引擎该有**资源管线**（加载/缓存/释放），本作**当前不喂素材给它** |
| 骨骼动画 | **内容决定**（纯 2D 程序化） | ⚠️ **要改**：引擎该有**时间轴/动画抽象**，本作**用它做程序化动画** |
| 3D | **内容决定** | ✅ 保留（引擎侧也不该做 —— 这是产品定位） |

## 五、这条方法学怎么被守住（不许只靠自觉）

| 机制 | 守什么 |
| --- | --- |
| `tools/engine-boundary.mjs`（门 `engine-boundary`） | **边**：引擎不许 import 内容。这是机器可验的那一半 |
| 本文件 §一 的**禁用判据表** | 评审时一条否决意见如果形如"本作用不上"，**必须**先按 §二 的三问改写 |
| 引擎能力包（§三） | 抽象**必须**有工具侧的示例与测试 ⇒ 死代码门与守卫门不会放过空抽象 |
| `tools/naming.mjs`（门 `naming`） | **名**：引擎模块里**不许出现内容的名字**（今天有 **17 处欠账**，那张表**只许变短**）。这是用户那句"**不要混了**"的机器判据 |
| **账本 [§八点七 引擎能力总表](../docs/requirements.md)（唯一一份）** | 每条能力的读数栏**只许**填引擎侧读数（**抽象 / 示例 / 门**），**不许**填"本作现在用不用得上"。⚠ 这条信息一度住在**四处**（R51 那张 21 行表 · §八点六 的 24 条 · 本文件 §九 · `teapot-restructure.md` §四）⇒ 2026-10-01 已收成 §八点七 **一份**，其余一律**指向它** |

## 六、这张判据表**不许**被用来绕过质量约束

⚠ 反向的滥用也要防住：**"引擎该有"不是"什么都能加"的借口。**

一条引擎能力进仓库，仍然要满足：
- **四步齐全**（声明表 / `BY_ID` / 启动期自检 / 注册 `Registry`）；
- **有机器判据**（门或测试），且**证明过它会失败**；
- **不引入运行时依赖**（`dependencies` 保持为空）；
- **不破坏行为指纹**（除非该能力**有意**改行为，那时走换基线的流程）；
- **记账**：gzip 预算超了要走 CHANGELOG 写明"多少 kB 是引擎"。

**做不到上面五条的，不是"引擎能力"，是"没做完的活"。**
